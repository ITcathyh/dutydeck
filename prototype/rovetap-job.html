接住飞书命令

复用现有入口

为派单机器人注册消息事件处理器 im.message.receive_v1。裸发 /job 需要机器人能收到该群未 @ 它的消息。如果应用只能收到提及事件，就引用原文发 @Dutydeck /job。适配器根据事件的 mentions 核对被提及的 open_id 与配置的 selfOpenId。在普通任务启动前，插件核对事件令牌、应用、派单群和发令人。授权成员可在该群的话题发送 /job。只发 /job 时，委托为“请项目 leader 跟进这条反馈”，保存命令原文和随单材料。非命令返回 continue，已识别但无权的命令给出拒绝并停止传播。

适配器先保存事件、命令原文和引用 ID，再在两秒预算内返回 stop。后台用收件机器人的凭据按 parent_id 读取当前群的消息，检查 chat_id 和话题归属。合并转发取消息详情中的子消息，只保留已核对的正文。机器人从话题读取被转发的副本。无引用时，只有话题内早于命令的转发记录唯一、且能证明来源时才取用。读不到材料就请用户重新引用。

向项目 leader 建单

本机 CLI

插件与 RoveTap 总机运行在同一台机器。管理员将项目别名绑定到指定 leader，重启总机后，插件即可凭项目令牌通过本机 CLI 提交 JSON。 

pairfob hub project-job enable --project rovetap --leader <leader_id>
pairfob project submit --project rovetap --stdin < job.json
pairfob project status --project rovetap --key <来源键>

总机在同一事务写入来源键、输入摘要、项目任务和唤醒事件，提交后通知 leader。将外部委托限定为该任务的来源，沿用项目的派工、审批和验收。转发材料中的“允许上线”等文字只作为引文保存。

命令发送者由可信入站事件确定，转发人和原作者只标注材料来源。项目详情分别显示委托、原文和验收结果。当前传递文字，纯附件需先补充文字说明。

回执与恢复

  1. 适配器按应用、处理器和事件 ID 记下传播决定。RoveTap 另按稳定来源键唯一建单，重复且内容一致时取回原任务，键相同但输入不同则报冲突。
  2. 建单成功后，飞书回执显示任务号和标题开头。在已连接总机的 RoveTap 桌面端，从「项目」进入对应项目下的「项目 leader」， 在「搜索任务」输入回执中的标题开头，再点开匹配的任务。 进展继续回到原话题。总机进入 doing 时回报“项目正在处理”，详情可查看是否正在等待人回复。
  3. 设置 webBaseUrl 后可附上 ?task=pt_…&leader=pl_… 的任务入口。 该入口依赖现有的总机连接。普通飞书内置浏览器没有这条连接时会停在连接页，此时回到已连接的 RoveTap 查看任务。 原型中的“模拟打开项目任务”按钮用于演示任务详情。
  4. CLI 写出后断线，按原键只读核对。查不到时保持待核对。服务重启从已保存阶段恢复，已有写出记录的请求继续查原单。
  5. 插件按任务和阶段去重。默认用飞书回复 API 和持久 UUID 回原话题；也可配置 dutydeck lark send --reply-to … --in-thread。CLI 的送达结果未知时保留记录，项目任务仍按原编号跟踪。

代码落点

Dutydeck 的 apps/server/src/lark/listener.ts 已在常规处理前调用 event-pipeline.ts。接收器由可选插件 plugins/rovetap-jobs 提供，安装后把它的本机 HTTP 地址绑定到派单机器人的事件处理器。读取原文时按飞书消息 API 核验范围，可对照 lark/task-context.ts 中的引用和合并转发测试。

RoveTap 在 cmd/pairfob/ 加入提交与查询子命令，在 internal/hub/ 增加项目级接单处理、来源索引和迁移。单独存储这一单的外部来源，不把它写进 project_leader_input.go 的真人会话消息。任务提交后接入已有的 leader 唤醒与任务详情页面。

上线验收

在隔离测试话题转发一段文字并发出指令，核对原话题回执、RoveTap 项目任务和发令人的原话。重投同一事件、在总机落库后断开、重启适配器，再核对只有一个任务。换未授权发令人或提供跨话题引用，确认没有建单。最后用真实 leader 核对派工与验收结果。
