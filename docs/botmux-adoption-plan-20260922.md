# Botmux 差异吸收实施计划

基线为 `f8c0b71`（`ceb72bd` 加评估报告）。本轮落实报告建议的五项差异；按人 CLI 授权另立能力范围。既有优化分支不整体移植。原 checkout 的未提交卡片改动保留，交付在 `feat/botmux-adoption-20260922` 独立 worktree。

Controller 负责设计、任务边界、调度、集成和验收；确定路径的实现由 worker 完成，writer 不提交。各 writer 使用独立 worktree。ccflash 连接失败后，已获用户确认改用原生 worker 接手。

| 执行单元 | 固定设计与边界 | 验收 |
|---|---|---|
| daemon 身份 | 保存 host/boot/namespace/PID/start 身份，每次信号前复核；旧记录无法证明归属时拒绝破坏性操作 | PID 复用、身份读取失败、TERM 期间身份变化、状态被新代替换、真实自有子进程生命周期 |
| CLI 输入就绪 | Codex/TraeX 当前视口底部可输入 composer，加 loading/resuming/busy/菜单/草稿反例；沿用 30 秒等待，不自动按键 | 上游真实 fixture、首轮/恢复/后续轮次、取消、其他 CLI 回归 |
| 剪贴板反馈 | Clipboard API 失败尝试 execCommand；仅实际成功显示已复制；失败可重试，临时节点和定时器清理 | DOM 点击、拒绝/false/异常、焦点与选区、卸载 |
| 编辑补 @ | 订阅 updated 事件，按 messageId 拉权威详情，恢复原作者和话题；仅人类明确 @ 当前 bot；复用权限及持久 inbox | 同 ID 首次触发、receive/update 并发、重启去重、富文本附件、权限及读取失败 |
| 显式最终答复 | `group send --final --turn` 绑定当前 task/attempt/目标；先发可更新卡并保存成功收据，成功终态在同卡补平台状态和验收 | 普通发送不抑制、旧轮/错误目标拒绝、并发和重启、存储失败、长结果、验证/导出/验收保留 |

显式 final 的收据与意图使用现有配置仓库，键和值均采用 snake_case。消息意图不是成功证据，只有平台确认且持久化的收据才可复用；失败或取消必须交付诊断。工具凭证留在提示词中，不修改 ACPX session 环境变量。进程内共享交付锁覆盖显式发送和终态检查，平台 UUID 负责发送重试去重。

顺序：先并行 daemon、CLI、剪贴板；controller 完成飞书两项接口设计后分别派发。整合时包含新增文件，依次应用各单元改动。运行定向回归、全仓测试与类型检查、packages/Web/server 构建、隔离链路验证，再由未参与编写的 reviewer 审完整 diff。采纳 finding 交原 writer 返修，复验后由 controller 提交。

真实飞书事件投递、应用发布、真实 CLI 版本矩阵和浏览器权限弹窗需要外部环境，代码测试不得表述为已经在线验证。本轮不推送、不发布、不重启现有服务。

独立设计复核补充：显式 final 回复失败不能退回群主会话，附件链同样严格匹配目标；重启恢复需保留 `final_card_input` 和实际验证能力；终态追加验收元素后再次检查卡片预算，必要时转附件并更新原卡。

未改动基线验证：类型检查通过；全仓测试 5074 项，5066 通过、7 跳过、1 失败。失败位于 `database-cli.test.ts:132`，固定期望 schema version 23，实际为迁移 `d97b197` 已加入的 24。本轮验收需区分该既有失败和新增回归，不通过削弱断言使结果变绿。
