# 通用群协作能力：实现与使用

本次把群上下文、按需发言、事项跟进和持续委托接入现有 Agent 运行时。具体业务通过群指令、Skill 或扩展接入；项目不内置报警、排班、服务树或业务任务同步。

## 使用上有什么变化

| 场景 | 行为 |
|---|---|
| Agent 刚进群或服务恢复 | 补读可访问的近期消息、群说明和记忆；重复材料合并，无法读取的内容明确显示缺失 |
| 群里普通讨论 | 开启观察后先积累上下文。只观察模式不主动发言；按需参与模式判断有价值才回复，沉默不发确认表情或过程卡 |
| 按需参与决定回复 | 先在源消息加 `OK` 表情，再生成正文；发送完成或失败后清理表情，生成失败时回复简短提示 |
| 明确下达任务 | 沿用现有 Agent、工具权限和任务交互；群长期指令进入执行上下文 |
| “跟进这份资料” | 记录目标、进展、步骤、可选负责人和期限。部分完成只更新相应步骤，执行结束不自动关闭事项 |
| “每天总结”“还没进展再提醒” | 保存持续委托，脱离当次会话继续检查。固定提醒直接发送，需要分析时启动有身份、有记录的后台任务 |
| “晚点提醒”“先别发消息”“取消” | 分别修改计划、暂停投递、取消执行。只有保存成功才确认变更；旧计划不能继续执行 |
| 消息发送结果不明 | 显示待核对，保留原动作编号，重启不盲目重发 |
| 纠正 Agent | 保存人工修订，按历史输入快照回放；材料缺失单列，不算通过 |

普通消息只读判断可以更新已有事项的进展、提出行动候选；创建委托、改期和取消通过明确群指令或管理页完成。历史消息、其他机器人发言和引用材料不能授予新权限。

不同群独立判定和生成回复，一个群的慢任务不会阻塞其他群。同群按顺序处理，未接下的连续消息合并判断；已加 `OK` 的回复使用接下时的材料完成，不会因普通新消息到达而丢弃。

## 在哪里启用

1. 在 Bot 接入页面配置执行 Agent、工作目录和监听，在「默认群参与模式」选择「仅观察」或「Tag 按需参与」。观察需要允许读取群聊内容，回复还需要允许主动往群里发消息。
2. 未单独配置的现有群与新加入的群自动继承该默认值，验证群身份后接入；保存默认模式不会重启监听，也不会对补读的历史消息自动回复。
3. 在「群管理」的「通用协作」中为某个群显式关闭、覆盖模式或修改长期指令；选择「跟随机器人默认」可恢复继承。已有群的显式设置及禁用状态保持不变。
4. 在事项、委托、动作核对和决策页查看状态；也可以 `@Agent` 用自然语言创建或调整委托。

Bot 默认参与方式初始为 `off`，沿用原群规则：原来允许普通消息唤醒的群仍按原设置工作。`off` 不取消已有持续委托。暂停主动通知、暂停某个委托的执行、取消委托分别管理；完成事项也是单独操作。

委托支持一次性、间隔、cron 计划及时区；条件包括按时执行、关联事项未完成、关联事项无新进展。发生新进展后，间隔型“无进展”提醒从该进展保存时间重新等待；cron 和一次性计划保留原约定时间。任务已在暂停通知期间结束时，该次结果保留记录，恢复后不补发积压消息。

## 权限与恢复

- 观察和主动回复来自管理员明确启用的 Bot 默认或群策略，并受现有读取、发送权限限制。后台执行绑定原委托人，工具调用、记忆访问和最终投递都复核当前权限。
- Agent 的协作写入凭证绑定当前指令。上一轮的凭证不能在下一轮沿用，请求体也不能指定其他群或伪造身份。
- 创建使用稳定请求编号；相同请求重试返回原记录，换参数不能冒用原编号。更新携带版本，冲突保留草稿。
- 调度只接管新的协作计划；原会话自动化和离线 staged 计划保持原入口。改期、暂停执行和取消会使旧执行失效。
- 单委托与全群的通知暂停只限制投递。分析可以继续；真正暂停执行或撤权会停止原后台任务。
- 普通主动回复和定时提醒共享群发言额度，默认每小时 6 次，可设为 0。普通回复在接下前检查材料版本，发送前仍复核群设置、监听状态和权限；定时提醒继续检查计划与事项是否有效。
- 重启使用原任务、原动作编号核对结果，不创建替代任务。外部系统未给出可靠回执时保留 `unknown`，不把重试当恢复。

## 定制接口

通过 `startLocalServer({ configureCollaborationExtensions })` 注册可信来源、只读查询和外部动作。来源自行验签并确定群与身份；查询返回带范围和时间的证据；动作提供稳定编号及结果核对方法。接口细节见[扩展说明](collaboration-extensions.md)。

管理 API 根路径为 `/api/lark/groups/:appId/:chatId/collaboration`。Agent 使用相同服务，但群和身份从当前会话获取，路径为 `/api/lark/agent-tools/collaboration`。

| 操作 | 方法与相对路径 |
|---|---|
| 查看状态 | `GET /` |
| 设置参与方式、长期指令、通知暂停 | `PATCH /settings` |
| 创建、更新事项 | `POST /followups`、`PATCH /followups/:id` |
| 创建、改期、暂停、取消委托 | `POST /mandates`、`PATCH /mandates/:id` |
| 保存人工纠正 | `POST /decisions/:id/feedback` |
| 只读回放 | `POST /replay` |
| 补读历史 | `POST /bootstrap` |

创建事项和委托必须提供稳定 `id`；修改必须提供 `expectedRevision`。Agent 的 `dutydeck collaborate` 命令由当前任务提示提供，携带本轮凭证。HTTP 传输成功且返回已保存记录后，才能对用户确认完成。

## 影响范围

新增 SQLite 协作表及调度执行迁移（版本 20、21），接入飞书消息入口、后台 Runtime、管理 API/CLI 和群管理页面。沿用现有运行时依赖，也不迁移原 `SessionAutomation`。协作数据按 Bot 与群隔离，近期观察记录默认保留 30 天；决策快照和执行审计保留用于核对与回放。

分析输入有大小限制；被裁剪的材料标记缺失，原始记录不会因此被改写。判定保存输入快照、策略版本、简短依据及证据引用，不保存内部推理过程。回放使用历史材料和选定的指令版本，由当前配置的 Agent 执行；不保证重现已变更的供应商模型。策略由管理员选择启用，项目不会自动修改业务规则。
