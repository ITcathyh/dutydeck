# Milo 群内发言模式观察

这些观察已纳入[通用群协作 Agent 能力方案](team-tag-foundation-plan.md)。

群内的具体业务仅用于观察参与和跟进行为，不构成本项目的业务功能要求；本项目的设计与验收只覆盖通用能力。

观察日期：2026-09-18，时间均为北京时间。样本来自「横向事务沟通」和「豆包 IM 小小群」，检索范围为 9 月 4 日至 9 月 18 日抓取时点；按 Milo 的发送者身份检索，分页结束，共取得 72 条消息，包含状态消息。已阅读这些消息，并补读重点话题的完整回复及相邻群消息。本报告只研究可见行为，没有访问 Milo 的配置、接收日志或执行轨迹，也没有重验它引用的业务数据。

**最值得借鉴的是：能接住长期委托，结合后续进展继续跟进，用具体信息帮助讨论往前走。** 对 Dutydeck 的启发是，除了判断当下要不要回复，还要记住自己答应跟进什么、下次何时检查，以及哪些变化值得通知。

**一个需要认真吸收的反例：少催不等于事情结束**

9/14 的值班计划话题提供了一条完整链路：

1. 14:24，人委托 Milo 跟进，当天下班前要结果。
2. Milo 随后多次提醒，18 点之后基本每半小时一次，内容变化很少。
3. 20:03，一位被催成员说“别催了”；20:05，Milo 回复已停止、不再追。
4. 20:07，委托人澄清：只是别这么频繁，今晚仍要结果。
5. 20:09，Milo 调整检查时间；21:31 跟进剩余项；22:31 向委托人说明仍未完整收齐，并保留待办。[来源](https://applink.feishu.cn/client/thread/open?open_chat_id=oc_e80bdc75717efee9c02ae3079dc59077&open_thread_id=omt_19c21bccc34e5c86&thread_position=10)

Dutydeck 应分别表达降低频率、暂停通知、取消委托和事项完成。它们改变的状态不同；谁能修改整个委托，也应由授权确定。对已有承诺，调整催办节奏后保留下一次检查与未完成项，避免频繁催促和直接遗忘之间来回切换。完成要求以委托或模板为依据，Agent 提议新增字段或截止时间时，应标明这是建议。

横向群也出现过类似反馈：9/4 上午 Milo 催补周报，被指出周会在下午 5 点、不要频繁提醒。它承诺临近会议集中一次，但当天可见记录中未发现后续集中提醒。因此该例只能证明接受纠正，不能证明计划已实际落地。[纠正与答复](https://applink.feishu.cn/client/thread/open?open_chat_id=oc_cfeb7abcb2f8d48fa4147b820e838b96&open_thread_id=omt_19ffb694e20fda78&thread_position=-1)

**据此细化首期方案**

| 改造 | 影响范围 | 收益 |
|---|---|---|
| 保留明确的持续委托 | 群内请求解析、事项记录、定时执行 | “帮我盯一下”“每天总结”能在当次回答结束后继续履行 |
| 将提醒状态与事项状态分开 | 事项记录、调度、权限检查 | 可以少催或暂缓，同时保留责任人、目标和剩余工作 |
| 发送前比较最新进展与上次通知 | 上下文读取、事项更新、投递 | 少重复，只催仍缺的内容；无变化且无期限触发时可以安静等待 |
| 明确消息类型与投递位置 | 回复生成、群配置、话题路由 | 普通回答简短；跟进说明缺项和下一步；日结按约定集中发 |
| 把人工纠正变成可核验状态变更 | 群配置、事项版本、调度记录、行为评估 | 能确认新计划生效、旧计划失效，避免只在聊天里答应 |

定时摘要与条件提醒应分别配置。样本中也有“今日无新增事项”的日结；它符合每天发布的原始委托，不能直接判为错误。新委托可以约定“没有变化则不发”，已接受的每日汇报不能擅自改成跳过。

首期可用这些脱敏案例验证：已有成员处理时不抢答；长期委托按约定执行；部分完成后只追剩余项；降低提醒频率后仍保留事项；取消委托后旧提醒失效；临近期限按约定回报；普通回复与日结发到正确位置。

**观察边界**

聊天记录只能显示它说了什么，以及部分后续动作是否出现。没有 Milo 发言的讨论，不能直接证明它读取并正确选择了沉默；也可能未接收事件或未触发执行。本次不计算介入准确率，不从消息文本推断底层采用何种模型、记忆或调度实现。引用的文档、表格和代码链接只作为其回答带来源的证据，不代表本轮核验了其中的业务结论。以上均为对 Dutydeck 的设计建议，尚未实现。
