| 用户反馈 | 本轮处理 | 实际影响 |
|---|---|---|
| 长会话仍要加载完整历史，可以显示 loading 或渐进展示 | 先显示最近的记录，随后自动逐页读完全部历史，显示已加载条数；普通会话和分享页一致 | 不需要上翻触发加载；全部历史最终仍会下载并保留，收益主要是更早看到内容、加载时仍可操作 |

| 分类、回复、记忆分开选模型只作为可选项 | 分类和回复的独立设置放进默认折叠的可选区域；已有显式设置时展开 | 留空继续沿用原来的记忆模型或默认模型；展开、收起不填写或清除配置，也不会默认切换模型 |

## 跨群查询到底用在哪里

群开启自动参与后，未显式唤醒机器人的人类消息会进入“是否需要回应”的判断。旧代码先搜索其他群，再判断是否回应，因此“谢谢”“还在处理中”也可能引发额外查询。P1 已改为先判断，确定要回答且需要其他群证据时，再检索其他群。

例如，“帮我看看项目群那件事进展怎样”“汇总我在几个群里的工作”可能需要其他群的原始消息和跟进事项。检索按群名和文本相关度匹配，不按 tag 匹配；如果 tag 指 `@机器人`，这是显式唤醒入口，仍走原有执行流程。

长期记忆走独立流程。当前同一机器人的各群共享一份群记忆，因此本群判断仍可能用到从其他群积累的记忆。推迟跨群原文搜索不会关闭共享记忆，也不要求每次先扫描所有群才能读取记忆。

实现位置：`apps/server/src/lark/group-participation.ts`、`team-context.ts`、`readonly-decider.ts`、`memory.ts`。本轮未改这些后端行为。
