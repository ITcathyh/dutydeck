# Dockmux 1.0 验收矩阵

现有测试是回归基线，不等于 1.0 验收完成。

所有章节共同构成一次性交付门槛，不设可先行发布的精简子集。内部里程碑只用于安排并发和 Review，不构成可跳过剩余项的发布点。

## Web

- 用户无需理解 Session 即可从工作区创建任务。
- 首页与工作区能区分运行中、排队、待处理、失败、完成和归档任务。
- 任务详情能看到当前焦点、精简活动、最终结果、审批、文件/命令/检查证据、日志和可用终端。
- 排队、立即介入、中断、重试、模型选择、文件引用和归档保持可达。
- 桌面、窄屏、键盘操作和 reduced-motion 有自动化覆盖。

## 飞书

- 私聊与群聊 @ 能快速确认，并在正确回复/话题范围创建唯一任务卡片。
- 排队、运行、待决策、完成、中断、失败拥有清晰且快照覆盖的视觉层级。
- 重复 trace 被聚合；完成态先展示结论与验证证据。
- 卡片不泄露凭证或原始思维链。
- 限流、卡片失效、瞬时更新失败和 daemon 重启不会制造冲突终态。
- 缺权限、身份歧义和风险限制提供可执行说明，不增加重复门禁。
- 工作台可自动配置精确的 Dockmux 权限、消息事件和卡片回调；扫码、配置、成功、失败均有可读状态，且不申请用户身份发消息权限。
- 自动配置对真实开放平台目录的无 bucket 响应兼容；事件/回调必须回读为长连接，发版保留既有白/黑名单可见范围，任何不可解析响应都不得创建版本。

## Runtime 与存储

- 排队任务恢复时不丢 agent prompt 和风险策略；来源、Agent、模型与工作区从持久化 Session 恢复。
- 非正常退出后，运行中任务明确中断；队列可以继续处理。
- 历史事件默认有界读取，SSE 重连不丢不重终态。
- 旧数据库可迁移并保持历史可读；失败迁移不破坏原数据。
- ACPX 环境持久化只包含 snake_case 键；相关修改由真实 `AcpxAdapter` 回归覆盖。

## 性能预算

- 5 万事件任务首个可见屏幕本机 p95 小于 800ms。
- 真实 Chromium 加载上一页并完成布局与两帧绘制的 p95 小于 250ms。
- 增量事件到界面更新 p95 小于 80ms。
- 常规历史分页 API 本机 p95 小于 100ms。
- Web 主入口目标不高于 140KB gzip，终端等重功能保持懒加载。
- 100 次 SSE 重连后无订阅泄漏，服务端 RSS 增长不高于 64MB；慢客户端回放遵守 socket 背压，实时待发队列有界。

## 发布证据

```bash
pnpm test
pnpm typecheck
pnpm build
pnpm smoke
pnpm benchmark
```

另外需要：旧库迁移、kill/restart 队列恢复、长历史基准、远程认证、飞书各状态卡片、认证 Agent 真实 fresh/resume/interrupt，以及真实 ACPX 持久化回归。

所有 HTTP E2E 必须断言状态码，并从本轮开始前记录的 sequence 游标判断新事件，不能用历史回放误报成功。

每个实现工作流由未参与该目录编码的独立 subagent review。Review 必须明确检查：是否存在无当前用户路径支撑的抽象、重复门禁、伪操作、配置膨胀或无法验收的状态。
