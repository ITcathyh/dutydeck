# Dutydeck 稳定性与性能审查

基线：`083f360af9dea75c94f2829a7c236a56a450f6f4`。工作分支：`fix/stability-20261022`。

本轮由四路 Astra 分别审查运行时与终端、服务端与存储、Web、插件与部署基础设施；修复在独立 worktree 实施，另由未参与编写的 Astra 复审整合改动。范围覆盖主要生命周期、数据流和故障边界，不等于逐行证明全部源码无缺陷。没有操作线上服务、数据库、凭据或 systemd unit。

| 问题与触发 | 修复 | 保留的行为与验证 |

## 性能证据

下表来自本机临时 SQLite、合成 transcript 和 Chromium，不能换算为线上整体收益。查询次数和数据完整性断言与计时分开验证。

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 1,000 条已关闭卡，initialize 全量查询 / 读取行数 | 1,002 / 1,002,000 | 2 / 2,000 |
| 同样本 reconcile 全量查询 / 读取行数 | 1,002 / 1,002,000 | 2 / 2,000 |
| 同样本 initialize / reconcile 耗时 | 3,248 / 3,262 ms | 85 / 75 ms |
| 1,000 条结果反馈权威读取 | 1,000 次 list、1,000,000 行 | 1,000 次 get、无 list |
| 同样本结果反馈读取耗时 | 2,977 ms | 81 ms |
| 134,383,456 bytes 来源核验，三个场景最大定时器间隔 | 196.51–214.85 ms | 1.66–1.99 ms |

来源核验分别覆盖无 marker、文件尾有效 marker、文件尾冲突 marker；同步与异步的完整结果一致。优化降低事件循环阻塞，总扫描耗时不保证下降。现有同步 checkpoint API、候选枚举和单条超大 JSON 解析仍有同步段。

## 边界与升级

- 保留历史自动补齐、完整原始日志、卡片提醒与重试，不以删数据、收紧展示或减少归属校验换性能。已关闭卡的查询优化不等于大量活跃卡关闭重试的所有路径均已变为线性。
- 密钥包新增的是项目已有版本的 `better-sqlite3` 依赖。新旧密钥写入端不共用锁协议，升级需同步更新写入端；旧锁文件保留，新 SQLite 锁文件不能在仍可能使用时删除。进程崩溃后可重新拿锁，不代表自动完成中断的部署事务。
- sessions 的 `updatedAt` 是墙钟时间，不是严格递增版本；时钟逆跳下的绝对顺序仍无法仅由现有响应证明。
- 未验证真实模型调用、真实飞书网络、真实 systemd 部署、Windows/macOS 或生产容量。长单轮大 Markdown/高亮成本没有新增可信实测，标记为 **unverified**，未据此修改产品。没有声称项目达到可证明的绝对最优。

原始审查、复现和基线/最终门禁日志保存在本工作树 `artifacts/stability-20261022/`；运行时、飞书、Web 的实现证据分别在 `artifacts/stability-runtime-20261022/`、`artifacts/stability-lark-20261022/`、`artifacts/stability-web-20261022/`。这些本地产物不纳入版本控制。
