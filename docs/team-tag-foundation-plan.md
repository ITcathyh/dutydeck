# 通用群协作 Agent 能力方案

方案日期：2026-09-18。依据：[代码与产品调研](team-tag-foundation-research-20260918.md)、[Milo 实际发言观察](milo-speaking-patterns-20260918.md)。本文确定实施方向和范围；实现与使用说明见[通用协作实现](generic-collaboration-implementation.md)，具体交付状态以该页验收记录为准。

**本项目只建设通用 Agent 能力：群上下文、选择性参与、持续委托、轻量跟进记录、条件触发与可控投递。** 团队 Tag 是使用场景之一，其业务流程由使用方在项目外配置或实现。本项目提供必要的扩展接口，不交付具体业务应用或其适配器。

报警识别与分级、故障档案、已知问题登记与折叠、Oncall 流程、服务树、Argos/RCA，以及指定业务的任务同步，均不属于本项目的首期或后续交付。下面的对象、行为与验收全部采用通用场景。

**使用效果**

Agent 进入授权群后，读取群说明、允许访问的近期消息、相关话题和既有记忆，了解当前正在处理什么。后续消息先更新上下文；有人明确请求时响应，有新增信息或受托事项需要推进时按策略介入，普通交流保持安静。

“帮我盯一下”“每天晚上总结”会成为持续委托，当次回答结束后仍有效。有人认领、补充进展、要求晚点提醒或取消时，Agent 更新正在跟进的状态。发言以新信息、具体缺项和下一步为主，细节回复原话题，约定的群摘要集中投递。

**处理流程与责任**

```text
群消息 / 已授权外部事件 / 到期检查
  → 校验来源、权限与重复投递
  → 更新群上下文，关联事项和持续委托
  → 判断状态如何变化、是否需要行动、是否需要发言
  → 运行时校验并保存状态，必要时调用现有 Agent 执行
  → 发送前复核最新进展、权限和投递位置
  → 保存结果；更新下一次检查
```

模型负责理解材料、提出状态变化和动作；运行时负责授权、状态版本、调度、停止和投递。状态更新与发言分别判断：允许更新跟进记录但不发消息，也允许回答问题而不新建记录。不默认给每条消息或每个话题建档。主动判定阶段只读；实际写入和外部动作经过运行时校验。

| 能力 | 定下来的做法 | 影响范围与收益 |
|---|---|---|
| 群观察 | 消息不因未唤醒 Agent 就直接跳过观察；保存必要来源、游标和关联，按保留期处理。入群初始化、历史补读与实时消息按来源 ID 去重 | 改消息入口和上下文读取，使未被 @ 的讨论也能成为后续材料 |
| 选择性参与 | 确定规则处理权限、重复投递和自身消息；其余结合话题、事项、委托及近期输出判断。连续消息可合并处理，避免每条都启动执行 | 在执行前增加判断，投递层保证沉默时没有回执、过程卡或空结果 |
| 跟进记录与持续委托 | 保存用户需要持续跟进的目标、进展和 Agent 承诺，关联现有任务 | 一次执行结束后仍能跟进，固定日结也无需创建额外事项 |
| 条件触发与提醒 | 到期或相关状态变化时检查条件；支持调频、暂停、恢复、取消和终止。确定内容直接发送，需要重新分析才调用 Agent | 补全独立调度的执行链，支持“到时仍没结果再提醒”等通用委托 |
| 群定制与扩展接口 | 沿用 Bot 指令、群覆盖、Agent/Skill；补群长期指令的生效链及来源/查询/动作注册接口 | 使用方通过配置或外部扩展接入场景，本项目不承担业务实现 |
| 反馈与验证 | 首期保存发言和沉默的简短决策依据、来源、规则版本、人工修订及动作结果 | 可以排查误介入和遗漏，为后续规则迭代提供样本 |

**最小状态模型**

| 对象 | 保存什么 | 与现有能力的关系 |
|---|---|---|
| 观察记录 | 来源事件 ID、发生/接收时间、发送者类型、群/话题、证据引用、处理位置 | 区分投递去重与业务关联；同类新事件保留新出现事实 |
| 跟进记录（事项） | 目标、状态、进展、来源、时间线、版本，可选负责人、期限、结果和外部引用 | 一条记录可关联多次 WorkItem/Task；字段和结束条件按委托配置，不内置业务状态机，执行完成不自动等于事项完成 |
| 持续委托 | 委托人或预配置策略来源、目标、作用范围、关联事项（可选）、检查/投递约定、停止条件、版本 | 同时支持“跟进这件事”和“每天汇总”；一次性问答不创建持续委托 |
| 检查与投递记录 | 到期条件、所属委托、计划版本、执行/发送结果、下次检查 | 复用现有调度、执行及投递基础，保存成功、失败或待核对状态 |

原始材料、模型推断、人工确认分别保留。长期记忆继续保存群偏好和精炼经验，事项状态留在结构化记录中。自动提取记忆补上来源身份与允许提取的范围；记忆和引用材料不能赋予执行权限。

**发言与提醒规则**

- 新启用的授权试点群先观察和记录，显式 @ 正常响应，已接受的委托按计划履行。额外的主动补充先记录候选决策，通过脱敏案例和试点检查后逐群开启；既有群模式不自动迁移。
- 主动发言要有明确用途：补充有来源的新信息、处理无人承接且属于授权范围的问题、履行已接受的委托，或按既定条件提醒。有人正在正常处理、没有新信息且未到约定节点时保持安静。
- “仅 @”等设置控制普通消息的参与方式；已存在的持续委托单独展示和管理。暂停群内投递时，所有主动通知都受约束，不通过委托绕过。
- 发言前检查最新消息与事项版本；别人已经解决或指出原结论失效时，取消或重算待发内容。设置每群主动通知次数与并发上限，提醒重复不因改写文案就视为新信息。
- 降低频率只改检查/通知节奏；暂停通知保留事项；取消委托停止其后续执行；确认完成才关闭事项。变更按授权处理并使旧计划失效。
- 部分完成只追剩余项；有关联的状态变化时重新判断提醒条件。“有人回复了”不自动等于目标完成，系统按委托约定判断下一步。
- 完成要求和截止时间来自委托或配置。模糊指代先澄清，Agent 新增的要求明确标为建议。人工确认沿用已有交互能力，按动作策略选择；不要求每条记录必经结论卡或人工审批。
- 定时摘要按委托约定执行；新委托可约定无变化则不发，已有每天发布的约定不被擅自跳过。停催和改期等自然语言操作只在状态更新成功后确认。

**调度与运行的具体取舍**

新增群级委托和事项提醒由现有独立 `ScheduleFoundation` 承载，补全启用状态、到期领取、执行状态推进、取消/恢复与投递结果记录。已有 `SessionAutomation` 继续承载原会话计划，本期不做迁移；一个计划只归一个调度路径管理，避免两边重复执行。

执行前校验委托是否有效、计划版本是否最新、事项条件是否仍成立、当前是否有权限。重启恢复时重新评估逾期计划，按委托的补偿策略合并或跳过，不能把积压提醒一次发完。发送意图和稳定动作标识先落库，再调用投递；结果不明时查询或进入待核对，避免盲目重发。

需要推理和工具操作时，继续使用现有 Agent、Task 与 WorkItem；确定内容的提醒直接使用投递能力。授权明确后台使用的身份和范围，群材料不能改变它。先修复调研中发现的取消/停止回归，再扩大后台执行。

部署延续单实例和 SQLite，补监听中断/积压可见性及备份恢复验证。群管理页增加必要的参与设置、长期指令、持续委托与跟进记录查看入口，状态修改、改期、暂停和取消优先复用现有群交互能力。

**适度开放定制**

| 扩展面 | 本项目提供 | 使用方提供 |
|---|---|---|
| 外部事件 | 来源身份、事件 ID、路由、幂等接收与处理状态 | 来源系统的接入及字段解释 |
| 上下文查询 | 可调用的查询接口，返回证据、时间、可见范围和缺失信息 | 到具体系统取数据、解析业务实体的逻辑 |
| 长期指令与状态解释 | 群级配置、轻量扩展字段、委托条件及版本 | 哪些信息重要、怎样算完成、何时需要处理 |
| 外部动作与交互 | 动作注册、参数校验、权限、执行状态、幂等与结果查询约定；复用现有表单/确认交互 | 具体 API 调用、身份映射和业务侧同步规则 |
| 评价 | 输入和输出快照、人工修订、规则版本、受控回放及对比 | 场景样本、评价标准及候选策略 |

首期只提供通用行为实际需要的配置和接口；通过简单测试扩展验证可接入性，不绑定具体外部产品。Skill 提供操作方法，外部扩展实现具体读写，运行时维护状态和权限。外部动作结果不明时支持查询或标为待核对，无法保证幂等的动作不能盲目重试。

现有飞书消息、话题和卡片能力继续作为交互入口；这不要求实现飞书任务等其他产品模块，也不预建插件市场、多 IM 平台或业务规则引擎。

**实施顺序与验收**

| 阶段 | 完整交付范围 | 通过标准 |
|---|---|---|
| 首期：通用群协作与持续执行 | 群上下文初始化与持续观察、选择性参与、轻量跟进记录与持续委托、独立调度执行、条件提醒及暂停/恢复/取消、群长期指令、来源及反馈记录、必要扩展接口 | 普通交流不发可见回执；重复事件不重复处理；委托跨多次执行保持；部分完成只追剩余；少催不丢事项；取消使旧提醒失效；重启后恢复正确；停止/取消回归通过。用人工标注的通用讨论检查误介入、漏记录、误记录和误提醒 |
| 第二期：完善扩展运行能力 | 外部事件、上下文查询、动作及结果查询的通用契约，补偿读取与状态回传 | 用测试扩展验证重复回调、成功后响应丢失、改期、取消和撤权；无需接入某个业务系统才能验收 |
| 第三期：评价与策略迭代 | 比较人工修订、版本化样本、离线回放、候选策略逐步启用与回滚 | 验证通用参与策略与委托执行行为；回放缺材料不得判为通过；隔离外部写动作；退化可回滚。领域评价与业务调优由使用方实现 |

通用验收场景采用“入群了解上下文”“讨论中按需补充信息”“每晚总结”“跟进一份材料的提交”“晚点再提醒”“取消这项委托”。验收不依赖报警、排班、服务树或外部任务系统。

首期用真实群确认入群前历史、其他机器人消息与卡片字段的可见性。未读到的材料明确标缺失，不推断成不存在；额外来源可由使用方通过已授权事件入口提供。先跑通上述通用链路，再扩大自由主动参与范围。
