# 飞书指挥台实战指南 <a id="lark-guide"></a>

> [← 返回 README](../../README.md) · [全部文档](../../README.md#docs) · [English](../en/lark.md)

飞书任务卡默认不显示 Agent 名称。在机器人设置的「访问范围与高级设置」中开启「卡片显示 Agent 名称」后，状态右侧会显示简称角标（例如 `完成` `CCFlash`），不展示括号中的宿主细节。也可用 `dutydeck settings bot set <appId> showAgentName=true` 开启，设为 `false` 关闭。

## 1. 经典任务交互流程

```text
[在飞书发送需求] ──► [机器人在原消息贴 👌] ──► [推送动态进度卡片]
                                                      │
┌─────────── Agent 要执行受控操作或需要澄清 ◄─────────┘
▼
[审批卡：允许本次 / 本会话允许此命令 / 本工作区允许此类命令 / 拒绝]  或  [提问卡：点选项或引用卡片回复]
│
▼
[任务结束] ──► [有验证命令则在本机运行验证] ──► [推送结果卡与附件]
```

1. **下达任务**：私聊直接说需求；群聊 `@机器人 任务描述`。
2. **跟进反馈**：接单后机器人在原消息上贴 `👌`，进度卡送达后撤销；关闭过程卡片展示时，`👌` 保留到任务返回结果（或完成表情）后再撤销。任务完成时在原消息上贴对勾，失败或中断（不含你自己取消）贴叉号。机器人开了「完成时只贴表情、不发结果卡」时，普通任务成功只贴完成表情；`/plan` 计划和飞书任务派发通道的任务仍发结果卡，计划卡带「批准执行」按钮，服务重启或发送失败后补发也按这条规则。
3. **在线审批**：审批卡顶部有一句操作摘要（如“执行命令：pnpm test”）。
   - 「允许本次」只放行这一次；「本会话允许此命令」只给发起人，且仅限非高危命令，放行后同一会话里同一条命令不再发卡；「拒绝」。
   - 「本工作区允许此类命令」：放行这一次，并把命令存为这个机器人在卡上显示的执行目录里的规则（如 `pnpm test`、`git status`；只有白名单里的测试、构建和只读 git 命令能建），之后同一机器人在同一执行目录里执行这条命令、只带允许的参数时自动允许，服务重启后仍有效。规则与范围见 [Agent 配置：按工作区记住的审批](agents.md#workspace-approval-rules)。只有机器人级管理员能点（接入群管理的机器人认不限定群的管理员角色，群管理员不行；未接入群管理的机器人只认非空的访问白名单里的人），点的人还要能批准这条请求。自动允许的请求不再发卡，进度卡上那条权限记录标注「按工作区规则自动允许：<规则>」。卡上写明风险：允许 `pnpm test` 后，Agent 改了 package.json 里的脚本，就能借这条命令执行任意代码。
   - 卡片上的「拒绝并说明」输入框可写下原因再提交：授权与「拒绝」相同，原因会转告 Agent（支持远程审批的终端模式 CLI 会把它作为拒绝消息收到，ACP 类 Agent 暂不转达）、记入审批记录，并以脱敏、截断后的摘要显示在收起后的卡片上；Web 任务时间线上的审批卡同样提供「拒绝并说明」，历史里显示「已拒绝：原因」。
   - 30 分钟没人处理会提醒一次，任务继续等；超过 24 小时自动拒绝。
4. **澄清答复**：Agent 发来提问卡时，点选项，或引用该卡片直接回复答案。带选项的提问卡在选项下方有可选的「其他」输入框：单选卡填写后点「提交其他答案」，以你写的文字为答案；多选卡的输入框在同一表单里，选项和文字都填时一次提交，Agent 收到的回答分两行写明“所选项”和“补充文字”，只填文字也可以提交；文字最多 1000 字。点选项仍然直接提交；整卡放不下输入框时，只保留选项按钮。ADHD 友好输出下的提问卡只保留问题和按钮，没有这个输入框。问题和全部选项优先完整展示；超出卡片容量时提供全文附件，并明确标注卡面为节选。附件发送成功前暂不发布可作答的飞书提问卡，恢复后继续投递；回答或过期后的卡片保留当时展示的内容。审批卡仍只显示脱敏内容，不把原始命令作为全文附件发送。
5. **交付验收**：结果卡包含改动摘要、验证结果（通过 / 未通过 / 未验证 / 已过期）和超长 Markdown 附件；有改动的轮次带「查看改动」链接。结论后的「需要你：…」提示会单独显示为醒目块，标签加粗。Agent 正文里紧贴 `**` 的中文标点（如 `**结论：**正文`）会在发卡前挪到粗体外侧（`**结论**：正文`），避免飞书把星号原样显示；代码、行内代码和链接文字不改，本来就能正常显示的内容（含跨行粗体）保持原样；正文超过 16KB 或 `**` 超过 2000 处时不做这项修复。任务完成、等待决策和验证结果分别标明；本轮完成不代表验证通过。

## 附件读取与结果投递

结果卡和执行记录导出会按凭据规则脱敏文本；JSON 凭据值中的转义引号不会提前结束脱敏，也会保留后续非敏感字段和命令。

卡片的 Markdown 图片和结构化图片共用最多 4 张的读取上限，并去重；Markdown 中仅识别实际图片语法里的合法飞书 `img_key`，代码示例和普通图片 URL 不会触发下载。

飞书文件遇到平台明确的尺寸限制后，使用原机器人身份分片下载并流式落盘，每片不超过 32 MB。Dutydeck 的单文件本地上限为 **512 MiB**，这不是飞书的平台上限；图片不走分片下载。权限或保密拒绝不会绕过，失败、取消或超时不会把半成品交给 Agent。总期限沿用现有请求设置（默认 15 秒），慢速大文件可能需要重新提供较小文件。

下载的附件保存在当前数据库所属的实例目录。排队、执行中、待确认、可恢复或结果未知任务持有的附件，以及正在下载的目录，不因超过 24 小时而删除；只有已无持有者且目录超过 24 小时的附件才在后续清扫时回收。完整引用集合读取失败或交接期间发生变化时跳过本轮清扫。旧共享临时目录中无法确认归属的附件保留，不自动迁移或删除。

过程卡和结果的写请求在限流等待、重试后重新确认任务和轮次归属，停止或换轮后不再继续旧轮写入；已经发出的请求无法撤销。最终结果被明确的内容安全审核拒收时，停止原文重发，并尝试发送不含原文的固定提示；提示成功不代表结果已送达，也不会改成附件绕过审核。

结果首次投递前记录时间；发送结果未知时，跨重启仍只在首次投递起一小时内自动重试。超过窗口后停止重发，需核查原话题和 Web 执行记录；已确认的送达回执仍可恢复。这不保证远端只执行一次。

### Agent 提前交付与自定义最终卡

飞书当前轮的 Agent 可用 `dutydeck agent --turn "$TURN" group send '完整答复' --final` 提前交付最终结果。默认 `--delivery publish` 发到本轮原回复位置；`--delivery reply-agent` 只向交接任务的机器人回传摘要，`--delivery both` 同时发布并回传。回传要求原消息来自可解析且仍在当前群内的机器人，宿主在发布前核对目标。首次提交后，正文、卡片、模式和目标固定，重试须保持一致；发布成功而回传失败时只补回传，完成或重启恢复不会另发一份已确认的结果。

自定义卡片使用静态 Card 2.0 **body**，不包含 `schema`、`header` 或 `config`。例如 `/path/body.json`：

```json
{"elements":[{"tag":"markdown","content":"**结论**：已完成"},{"tag":"hr"}]}
```

```bash
dutydeck agent --turn "$TURN" group send '可检索摘要' --final --card-file /path/body.json --delivery both
```

摘要必填，但不必重复整张卡的数据。body 最多 28,000 字节，仅接受白名单内的静态文本、图片、布局和表格等组件；交互组件、回调、`element_id` 和脚本 URL 会被拒绝，具体样式仍由飞书校验。`reply-agent` 只接受摘要，不接受发布卡片。宿主继续管理状态、原回复位置、任务与轮次校验及完成收尾；平台拒收自定义 body 时不会替换成另一份结果。旧的 `dutydeck group send` 同样支持这些参数。命令需要当前会话的工具凭证和宿主给出的本轮 `--turn`；缺失、过期或属于其他执行的凭证会被拒绝。示例中的 `$TURN` 代表本轮凭证。

## 结果未知的任务

重启、断线等情况下，一轮任务可能“不知道是否执行成功”。这时飞书原话题会收到一张提醒卡，有「重新执行 / 标为已完成 / 标为失败」三个按钮和「查看详情」链接。

- 发起人和管理员可以操作。「重新执行」需要在 60 秒内再点一次确认。
- 插话投递结果未知时，回执也会指向这张卡。
- Web 会话详情页执行记录下方有同样三个操作，重新执行要在确认框里确认。
- 处理后卡片上会显示谁在何时做了什么；处理记录写入执行账本。
- 超过 24 小时的旧任务不发飞书卡，只能在 Web 上处理。
- 接口：`GET /api/sessions/:id/unknown-tasks`、`POST /api/sessions/:id/unknown-tasks/:taskId`，body 为 `{target, action, allowDuplicateEffects?}`。
- 驱动能确认 prompt 还没写入就失败的（例如 Codex/Claude 启动尚未就绪、停在目录信任页），不算结果未知，直接记为失败，可以重发。
- 服务重启切断的一轮，只有执行记录能证明只做过只读操作时才在原对话自动继续（1 小时内、最多 2 次）。终端模式的 Agent 没有转写、或这一轮没有任何工具记录时无从核对，一律停在这张卡上等人选择。
- 重启时还没记下已受理的消息按执行账本处理：账本已接收的照常接回结果，不会再执行一次；超过 1 小时且账本没有接收的不再自动执行，原话题提示重新发送；账本读不到时只提示结果未知，不自动重发。
- Claude Code 启动时停在等人回答的确认框（是否允许导入工作目录外的 CLAUDE.md、是否启用项目里的 MCP 服务、是否接受跳过权限确认模式），Dutydeck 不代答，立即按上一条记为失败，结果里写明是哪个确认框；在终端里选择后重发即可。飞书群记忆、群参与判断和回复生成这类后台作业只加载用户级设置，不读所在代码仓库的 CLAUDE.md、项目设置和 .mcp.json，不会停在这些确认框上；记忆作业没跑完就失败时，它的会话和终端随之关闭，下次换新会话。
- 超过 24 小时没人处理，原话题和 Web 会话里各有一条提醒，说明怎么处理；超过 7 天、且确认执行它的进程已退出时，自动按「结果未知、已放弃」结案：不重做、不算完成，决定和证据写进执行账本，原话题再通知一次。会话里还有排队消息时不自动结案。

排队任务被同一仓库里的未结任务或残留终端挡住时，被挡的会话（Web 时间线；飞书会话发到原话题，任务卡上已写明受阻的不另发）会收到一条提醒，写明挡住它的会话和任务、怎么处理，处理后自动继续；同一条排队任务只提醒一次，服务日志记一条告警。正常排队（前面的任务还在跑）只记日志，不提醒。排队超过 24 小时仍未开始的消息，轮到它时不再执行，改为取消，并在会话里提醒“需要的话请重发”；同一会话上一条任务刚由 Agent 跑完（15 分钟内）、按顺序轮到的照常执行。定时任务的这一次按未执行处理，下次照常触发。飞书群记忆作业不适用上述 24 小时排队取消规则；它们不参与仓库互斥，只和在同一记忆目录里执行的会话互斥。

管理员可用 `dutydeck recovery`（只连本机 runtime）处理阻塞：
- `inspect <会话 ID>` 查看阻塞项和运行 ID。
- `retire-pty <会话 ID> --file <决定>` 回收残留终端。原 tmux 名称及其所有者标记对应的会话均不存在、且记录它的旧服务进程已退出时，记为已消失；会话改名后不算消失。socket 文件缺失时，仅在 Linux 核实没有服务仍绑定该路径后回收，查不准则保留待核对。服务启动时也会自动回收这类记录。
- `restore-configuration <会话 ID> --run-id <运行 ID>`：模型或权限修改结果不明（`DRIVER_CONFIGURATION_UNKNOWN`）时，用原生会话重新下发并核实当前配置，不发送任何 prompt。接口 `POST /api/sessions/:id/recovery/restore-configuration`，body 为 `{runId}`。原生加载或配置回执失败返回 `409 NATIVE_CONFIGURATION_RESTORE_FAILED`，保留配置阻塞和调用前状态；旧版本遗留的 `starting` 在失败后变为 `failed`。原生记录已丢失时，须先检查恢复证据，再显式 `replace-native`；不会自动创建新原生会话。

恢复提醒会随解除阻塞、开始执行和本轮结束原地更新；静默进展与重启对账也会同步。已确认空闲且没有后台任务的旧会话不会被误报为阻塞；已开始的任务不再显示工作区排队阻塞。

## 推送分级

群里的 @ 和加急按事情的轻重分三档，由三项机器人设置控制（Web 高级设置，或 `dutydeck settings bot set <appId> ...`）。三项都在“群卡片 @”总开关打开时才生效。

| 档位 | 包含 | @ 谁 | 加急 |
|---|---|---|---|
| 需要你操作 | 审批、提问、结果未知、任务恢复提醒 | 发起人 / 能批准的人（`notifyMentionAction`，默认 `true`） | 到阈值未处理会加急（审批、提问、结果未知卡） |
| 完成 | 结果卡、启动前失败 | 发起人（`notifyMentionDone`，默认 `true`） | 不加急 |
| 信息 | 进度、回执、排队 | 不 @ | 不加急 |

- `notifyQuietHours`（如 `22:00-08:00`，daemon 本地时区，空则关闭）：免打扰时段内完成档不 @；需要操作档照常 @，加急推迟到时段结束后补发一次。
- 启用加急后，同一机器人内同一张卡最多加急一次，每个群每小时的加急次数有上限（默认 3 次，`urgentMaxPerHourPerChat`）。并发的加急检查同样占用同卡和本群名额，不会重复发出；发送失败的加急释放名额，下次检查可以重试。
- 定时任务的结果不 @。

## 2. 常用飞书命令速查表

不记命令也行：直接对机器人说要做什么（如“换 codex 重新做”“看看状态”“把这个群放开给所有人”），Agent 会替你执行对应的命令。查看类的结果由 Agent 在答复里告诉你，不另发卡；会改东西的先发确认卡，点「确认」才执行。停止任务、批准工具调用、回答 Agent 的提问仍由你点卡片按钮或直接说“停”“可以”。

下表与 `/help` 一致。`/help` 默认每页 6 条；装了插件命令时，插件命令列在最后一页。

| 指令 | 示例 | 作用说明 |
|---|---|---|
| `/help` | `/help 2` | 列出当前可用的命令及用法 |
| `/new` | `/new -- 优化登录接口的查询耗时` | 结束当前会话上下文；带任务内容则同时开新会话并派发 |
| `/new` 指定首轮配置 | `/new --cwd "/data/app" --workspace worktree -- 重构模块` | 选项：`--agent`、`--cwd`、`--workspace shared\|worktree`、`--model`、`--effort` |
| `/new --handoff` | `/new --handoff 接着补测试 -- 补齐重试逻辑单测` | 新会话带上上一会话的结果、git 状态和备注。`--handoff` 后到 `--` 之前是备注，任务写在 `--` 之后；不写 `--` 则只交接、不派任务 |
| `/resume [会话编号]` | `/resume`；`/resume list` | 恢复本话题最近关闭的会话；list 只列出你有恢复权限且能核实原请求人的最近 5 个会话的关闭时间、Agent 和首句任务，再按编号选。`/resume list` 只是查看：协作机器人也能发，Agent 代发时不弹确认卡。先按 /new 的方式结束当前会话，再接回旧上下文；归档、其他机器人或话题的会话不可恢复 |
| `/fork [任务]` | `/fork 检查另一种实现` | 带上下文在新话题开分身，原会话和队列继续运行。支持 /new 的首轮 Agent、模型、目录等选项；git 仓库默认独立 worktree。`/fork list`（只有单词 list 时）列出这个会话的所有分身：状态、Agent、最近更新和话题链接，在源会话或任一分身里查结果相同；只列同一个群里、你能查看结果的分身。`/fork list` 只是查看：协作机器人也能发，Agent 代发时不弹确认卡。想让分身的任务就叫 list，写成 `/fork -- list` |
| `/model [模型]`、`/effort [档位]` | `/model`；`/model gpt-5.5`；`/effort high` | 不带参数回当前值与可选项（用已缓存的 Agent 模型列表，不强制刷新）；带参数在会话空闲时切换，下一轮起生效，权限与 `/new --model` 相同（受管理的群需要群管理员权限）。查看与切换按同一份参数读 Agent 的模型列表，10 秒内读不到时查看回“暂时读取不到”，切换回执说明没有切换。本轮运行中会被拒绝，请等本轮结束；有待审批的请求或上一次配置变更还没完成时提示稍后再试；Agent 不支持在会话中切换时会写明原因。终端模式（命令行 Agent）的会话不支持会话内切换，`/model`、`/effort` 直接说明并建议用 `/new --model` / `/new --effort` 开新会话，不列档位。切换后重启服务或 `/resume`，仍是新值 |

恢复和分身也可以直接用大白话告诉 Agent，由它运行 `dutydeck agent --turn "$TURN" session resume [--id 编号]` 或 `dutydeck agent --turn "$TURN" session fork [--task 任务]`；它会先发确认卡，点确认后才执行。恢复失败会说明原因，并提示 `/new --handoff`。恢复尚未启动的任务时，创建会话前会按发起人的当前权限重新校验启动参数。

分身只允许源会话第一条任务的发起人操作，沿用原会话的 Agent、模型和推理强度，权限按机器人当前设置执行。Claude Code 终端模式用 `--resume 编号 --fork-session`，Codex 终端模式用 `fork 编号` 复制已落盘的上下文；ACP、其他 Agent、换 Agent 或找不到已落盘上下文时，改用 `/new --handoff` 的最近结果、git 状态和备注交接。交接还包含早期任务的来源索引、已知状态和命令回执，可按 task/attempt 在历史中查证；缺失或截断的材料会标明。原生分身已复制上下文时只补来源说明和 git 状态，不重复注入完整交接摘要。Codex 显式使用相同共享目录时走交接，避免后续把复制出来的记录误认成源会话。独立 worktree 从已提交的代码开始，不含原会话未提交的改动；首条消息会说明。分身回执能跳转到新话题。整段私聊共用一个会话时不能开分身，请先把机器人设置中的私聊模式改成“每条消息一个话题”。

> **提示**：`/new` 带选项时，选项和正文之间用 `--` 分隔，例如 `/new --workspace worktree --model "claude-sonnet-5-5" -- 修复单测`。

裸 `/new` 确实结束独立 worktree 会话、且配置了有效 Web 地址时，结束回执提供「检查并清理 worktree」链接，打开旧会话的登录工作台和「工作目录」面板。仍需点击预览并确认清理；正在使用或有未提交改动时会拒绝。打开链接不执行清理，也不解散群聊。`/stop` 只停止任务，不提供此清理入口。

### 先出计划（`/plan`）

`/plan <任务>` 让 Agent 先只调研、出计划，不改文件。计划出来后，卡片上可以：

- **批准执行**：在同一会话里按机器人原来的权限模式执行；
- **提修改意见**：写在卡片上，或引用计划卡回复，Agent 重出计划；
- **取消**。

要点：

- 计划阶段会拦下写文件和执行命令的工具调用，以及常见的写操作命令。它不是沙箱，挡不住刻意构造的 shell 命令，不要在计划阶段让 Agent 读不可信内容。
- 不带任务时返回用法。
- 支持 Claude 的 ACP 和 Claude 终端模式。其它 Agent（如 codex）会明确提示“无法先出计划”。计划功能上线前就已存在的终端会话，要先 `/new`。
- 批准、提修改意见、取消，权限和中断任务相同（发起人或管理员），不需要高风险审批权限。
- 沿用审批的时限：30 分钟提醒一次，24 小时没人处理就关闭；有了更新的任务，旧计划卡自动失效。
- Web 输入框旁有“先出计划”开关，但只对 Web 会话生效；计划待批准时，输入区上方显示“执行计划待批准”面板，可批准、取消或提修改意见。飞书会话需在飞书发送 `/plan <任务>` 发起，并在飞书计划卡上批准、提修改意见或取消。飞书发起的计划在 Web 上只读，Web 仍可在该会话发送普通消息。恢复出来的飞书计划草稿会保留正文和计划意图，不能直接发送：必须显式点“改为普通消息”清除计划标记后才能发出，不会自动降级为执行。

### 开 PR 与跟进（`/pr`）<a id="pr-loop"></a>

`/pr [标题]` 把当前会话的改动变成一个 PR。Web 里的入口是任务「结果检视」里的「开 PR」。

- **先确认，再推送**：先出确认卡（飞书）或确认框（Web），列出要提交的文件和增删行数、不包含的文件及原因、本地提交、源分支和目标分支、标题和正文摘要。有权限的人确认后才推送；清单 30 分钟过期。飞书沿用中断 / 重试同一道权限（发起人或管理员），Web 的生成、确认、取消也要求会话的中断权限。重复点或并发点只会推一次、只开一个 PR。
- **推送目标**：只推新建的 `dutydeck/<主题>-<8 位 id>` 分支，不用 force，不切换分支，不改动你正在用的检出（HEAD、暂存区、工作区文件都不变）。推送用本机的 git 凭据，所以本机要能 `git push` 到 `origin`。首次推送前远端已有同名分支会拒绝。
- **PR 描述与提交追溯**：PR 描述末尾写本会话最近一次验证记录（只写脱敏后的命令、结果、时间；验证之后代码又改过则注明“验证早于最后改动”；不写输出和目录；没有记录写“未验证”）和 DutyDeck 会话编号，纯文本，不含分享链接。DutyDeck 创建的提交（首次推送和之后每轮自动修复）在说明末尾带 git trailer `Dutydeck-Session: <会话编号>`（默认开启，不再另写“由 DutyDeck 会话 … 生成”那一句），可用 `git log --format=%(trailers)` 查看；git author / committer 不变。
- **推送地址核对**：
  - 代码推到 `origin` 当前的推送地址（配了 `pushurl` 就用它）。这个地址必须属于确认卡上写的仓库；指向别的仓库（如个人 fork）、配了多个推送地址，或还会被 `url.<地址>.insteadOf` 改写到别处时，不生成清单。核对推送地址需要 Git ≥ 2.31；更旧的 Git 会提示升级。
  - 确认后、每轮自动修复推送前都会再核对一次推送地址，和生成清单时不同就不推送：首次推送记为失败，需重新发起 `/pr`；自动跟进则停止。
  - 升级前生成、还没确认的清单，确认时不推送，需重新发起；升级前开出的 PR，下一次自动修复要推送时停止跟进。
  - 推送经临时 remote `dutydeck-<随机编号>` 进行：pre-push 钩子收到的 remote 名是它；本机不再因此更新 `origin/dutydeck/...` 跟踪分支，需要时自己 `git fetch`。仅给 `origin` 设置的选项（例如自定义接收命令 `remote.origin.receivepack`）也不会继承；依赖这类选项的仓库暂不支持通过 `/pr` 推送。
- **哪些文件会带上**：只带本会话某一轮改过、且之后没被别人再改的文件。其余的在清单里列为“不包含”：没有任何一轮改过的标“不是本会话改的”，改过之后又被改动的标“本会话改过，之后又被改动，无法确认”。生成清单到确认之间这些文件又变了，就不推送，需要重新发起。这依赖[每轮改动](web-console.md)的记录，没有记录的轮次不会进清单。
- **本地未推送的提交**：HEAD 上有不在 `origin/<目标分支>` 里的提交时，会作为 PR 分支的祖先一起推送（不改写），并在清单里逐条列出；没有 `origin/<目标分支>` 跟踪分支时会提示无法确认这些提交是否已在目标分支上。本地未推送的提交超过 50 个时不能开 PR（清单列不全），先把它们整理成少量提交再试。
- **工作区里有超限的未跟踪文件时**（单个超过 20 MiB、合计超过 50 MiB，或超过 2000 个），`/pr` 和自动跟进都会报出具体文件或原因，不会静默跳过。把不需要提交的文件和构建目录加进 `.gitignore` 后再试。
- **自动跟进**：开出 PR 后每 2 分钟查一次 PR 状态、当前提交的 CI 和新评论。
  - CI 失败：最多自动修 3 轮；同一个错误出现 2 次就停；每轮改动超过 10 个文件或 300 行就停。
  - 评审意见：最多 5 轮，每轮最多带 10 条评论。**只有仓库所有者、成员、协作者的个人账号**（GitHub 的 `author_association` 为 OWNER、MEMBER、COLLABORATOR，且不是 Bot）的评论会自动交给 Agent；其他人和机器人（如覆盖率机器人）的评论只发“需要你决定”卡片，卡片上写明作者和身份，点「按评论修改」才处理，这类评论不占处理轮次。Agent 对自动处理的每条评论给出“已处理”或“需要问人”：已处理的在 PR 上回复；含义不清的发卡片问人，按钮是「按评论修改」「不处理」。自己发的评论和带 `<!-- dutydeck -->` 标记的评论不会当作新意见，同一条评论不会重复处理。github 插件的令牌要能读到组织成员身份（例如 fine-grained PAT 要有组织 Members 读权限），否则把成员身份设为私密的成员发的评论会被当成外部评论，只发卡片。
  - 修复推到同一个分支，只做快进。远端分支被别人推过就停止跟进，不覆盖。
  - 推送前验证：会话所属机器人配了验证命令（机器人设置 `verificationCommand`）时，每轮自动修复（CI 失败、评审意见）改了代码、准备推送前，先在工作区跑一次这条命令，Web「开 PR」里显示“推送前验证中”。推送的是这一轮结束时的改动快照：验证前和推送前各核对一次，工作区里这一轮改的文件必须还是快照里的内容，否则按验证没通过处理。通过才推送，推送通知写明这一点，并说明工作区里不属于这个 PR 的未提交改动也参与了验证、推送的提交里没有它们。没通过（失败、超时、没能执行，或这一轮的文件在验证前后又被改动）时不推送、不提交，改动留在工作区，显示“验证未通过，等人处理”（和“已停止跟进”不同）；原话题收到一张卡，写失败的命令、退出码和末尾 4 KB 以内的脱敏输出，按钮是「仍然推送」（推送前的其余核对照做）和「停止跟进」，权限与确认卡相同；卡片没发出去时每隔约 2 分钟补发一次。Web「开 PR」里等人处理的记录也有「仍然推送」和「停止跟进」，权限与 Web 确认推送相同；CLI 没有这个入口。等人处理期间这个 PR 仍算在跟进，别的会话不能认领；「仍然推送」前会核对这条记录仍是这个 PR 唯一的跟进者。验证没通过不算新的修复轮次，也不自动重试。暂时情况不算失败，下次轮询（约 1 分钟）再验证：会话正忙或有别的验证在跑、会话正在停止、服务正在关闭、运行冲突或写冲突；会话已停止等其他错误按没通过处理。服务重启打断的验证会重新跑，不会直接推送；记下验证没通过后、PR 还没停下时重启，重启后会补成等人处理并补发卡片。没配验证命令的机器人和非飞书会话照旧直接推送，推送通知写“未配置验证命令”。
  - PR 合并或关闭、或在 Web 点「停止跟进」后不再跟进。
  - `/ci cancel` 或 Web「停止跟进」会拦下尚未提交的自动修复，已经开始执行的任务沿用现有语义（不强制中断）。修复推送后并发到达的流水线事件不会覆盖新提交，评论、待处理问题等跟进状态也保留。
  - 跟进时 Agent 直接改工作区，提示词禁止它自己 commit、push 或切分支，由 Dutydeck 把这一轮的改动提交到 PR 头上再推送。如果你在工作区里手改了 PR 涉及的文件，自动跟进会停下。修复这一轮改到的文件，如果在这一轮开始前就和 PR 分支不一致（里面有不属于这个 PR 的未提交改动，例如确认时被排除的本地修改），也不会推送：会停止跟进并列出这些文件，请人处理。修复只自动推送 PR 里已有的文件：这一轮改到别的文件（包括新建的文件，或这一轮期间被别的话题、编辑器改的文件）时不推送，停止跟进并列出这些文件；确认它们该进 PR 的话，自己提交并推到 PR 分支。
- **没装 CI 插件时**：`/pr` 回“开 PR 未配置”和安装方法；Web 不显示按钮，只显示同样的提示。

**认领已有的 PR（`/pr follow <PR 链接或编号>`）**：别人或你自己在平台上开的 PR，也可以交给当前会话跟进，之后按上面的“自动跟进”规则处理 CI 失败和评审意见，PR 合并或关闭后停止。Web 在「开 PR」下方的「跟进已有的 PR」填链接；CLI 是 `dutydeck pr follow <链接或编号> --session <会话>`（`dutydeck pr list|stop` 查看和停止）；API 是 `POST /api/sessions/:sessionId/pull-requests/follow`，请求体 `{"pullRequest":"<链接或编号>"}`。

- **权限**：和开 PR 相同。飞书要求发送者能操作这个会话（发起人或管理员），Web / API 要求会话的中断权限。
- **认领前核对**，不满足时不认领并说明原因：
  - PR 和会话工作区的 `origin` 是同一个仓库。链接用 CI 插件的仓库识别规则判断，不认识的链接或别的仓库的 PR 会被拒绝；只给编号时指工作区仓库里的 PR。
  - PR 还开着；已合并或已关闭的不认领。
  - PR 的源分支在这个仓库里（不是 fork），不是目标分支或默认分支；`origin` 上能取到这个分支，且就是平台给出的 PR 最新提交。CI 插件要能给出 PR 的源分支（仓库自带的 github 插件支持）。
  - 会话工作区里 PR 改到的文件和 PR 分支一致：先在工作区检出 PR 分支（`git fetch origin <分支> && git checkout <分支>`），并处理掉这些文件里的未提交改动。Dutydeck 不会替你切换检出。
  - 推送地址核对与开 PR 相同。
  - 同一个 PR 同时只能由一个会话跟进：同一会话重复认领返回原记录，另一个会话要先停止原来的跟进。
- **认领之后**：认领时 PR 上已有的评论算已处理，只跟进之后的新评论；可信评论的判定和上面相同（只有仓库所有者、成员、协作者的个人账号）。CI 从 PR 当前提交开始看。修复推到 PR 原来的源分支，只快进、不 force，也只推 PR 里已有的文件；有人另外推送了这个分支时停止跟进，不覆盖。

安装和令牌见[插件 → CI 提供方](plugins.md)。

## 3. 群聊协作机制

把机器人拉进团队群后：

- **参与强度**（群里不 @ 时机器人什么时候接话，只影响接不接话，不改变权限）：
  - `只在 @ 时`：只处理 @ 机器人的消息。
  - `话题内免 @`：新任务要 @；机器人接手的话题里直接回复即可。
  - `按需`（`selective`）：没 @ 时先判断是不是在叫它，是才接；有明确求助或紧迫风险时主动回答。
  - `积极`（`eager`）：除了明显对别人说的、表情和致谢，群里真人的消息都接，适合单人群。
  - 底层字段是 `mentionPolicy` 和群参与模式 `participation`（`off` / `observe` / `selective` / `eager`）。`observe` 只监听、沉淀背景、不发言，目前只能用 `dutydeck settings group set <chatId> participation=observe` 设置。
  - 新建机器人的 `mentionPolicy` 默认 `topic`。
  - **多机器人群**（本群订阅的告警来源不算）没指定接话人时，除了叫它名字、回复它和它接手的话题，没 @ 的消息都不接。@ 要接话的机器人说「你负责接话」并点确认，或在 Web 群设置里指定接话人；迟到的旧卸任声明不会清除更新的接话人记录。
  - **接话人**（多机器人群和单机器人群都能指定）：按需档的接话人没配负责范围时，群里没有明确对象、需要有机器人处理的求助（如「有人知道今天的发布单在哪看吗」）也由它接；闲聊、群友之间的问答、@ 别人和进度播报仍不接。
  - **负责范围**（Web「机器人管理」的「负责范围」，或 `dutydeck settings bot set <appId> roleScope=...`，对这个机器人所在的所有群生效）：按需档配了以后，没 @ 的消息里属于范围内的事由它判断后接，不受接话人限制；多个机器人的范围重叠时可能都接。按需档没配、它也不是接话人时，在有多个真人的群里，没明确叫它的泛问和普通告警不接。积极档和单真人群配了负责范围后也改为按范围判断，接的会变少。
  - 没接话时 @ 它问「刚才为什么没回」，它会说明原因和怎么改；`/status` 显示参与强度、接话人和负责范围。
- **机器人互聊门禁**（`botLoopGuard`）默认关闭。在机器人设置里打开，或执行 `dutydeck settings bot set <appId> botLoopGuard=true`；开启后同一话题连续 3 轮由机器人触发时，在真人发言前不再响应。关闭后不计数、不拦截机器人回合。
- **告警初筛**（内置场景包 `alarm`，见[内置插件](plugins.md#builtin-plugins)）：
  - @ 机器人说「告警来了先帮我看看」或「告警来了先帮我初筛，只看 P0」，它发一张确认卡，写明来源机器人（默认取最近在群里发言最多的机器人）、级别、去重窗口和每小时上限。点确认的人是确认人，初筛任务以他的名义发起。说「关闭告警初筛」并确认即可关闭，设置会保留。
  - 开启后，来源机器人发的告警不经参与判定：机器人在告警下开话题起初筛任务。同一条告警在去重窗口内只分析一次，超过每小时上限的跳过；在跳过的告警下 @ 它问「刚才为什么没回」能查到原因。多机器人群里只由接话人做。`/status` 显示订阅和今天分析、跳过的条数。
  - @ 机器人并引用一张告警卡时，如果它在这个群里处理过同一告警规则，会把上一次的结论作为参考材料带给 Agent，并在过程卡顶部挂一行「📎 日期 同一告警规则：…」。
  - Web 群设置按场景包列出参数（来源、级别、去重窗口、每小时上限）。开启要先在群里确认过一次；之后可以在 Web 或 `dutydeck settings group set <chatId> scenarios=...` 改参数和开关。Web 保存只提交改过的项；开始编辑后，如果同一群的分工已在别处（其他人、其他机器人或群里的确认卡）改过，保存会提示“群分工已被修改”，不覆盖对方，已填的内容保留，点「放弃修改」载入最新设置后再改。
  - 告警下的话题：多机器人群里，来源机器人发的告警开出的话题不算别的机器人的话题，有人在里面没 @ 地追问时照常走参与判定。机器人判定前会读这个话题的回复（每页 50 条、最多 4 页），发现别的机器人（来源机器人和自己以外）已在里面发过言、话题超过 4 页读不完或读取失败时让路，不接。两个机器人几乎同时判定时仍可能都接，这里不保证只有一个接。
- **团队答疑**（场景包 `team-faq`，在 `plugins/team-faq`，要先安装）：群里真人问到配置的服务或流程时，机器人按 runbook 判断要不要接，接了按 runbook 回答并标出处。安装和参数见[该插件的 README](../../plugins/team-faq/README.md)。
  - 只在 `按需` 和 `积极` 档生效；@ 机器人、回复机器人的消息照常处理。
  - 命中关键字只是把这条消息交给参与判定模型，并附上 runbook 摘录；同事之间的讨论、已经有人回答、runbook 没覆盖的问题，模型会不接。
  - runbook 读取超时或出错、或者一段都没读到而有文件读不到时，这条消息按没开这个包判定，`/status` 记为「取材料失败」，「为什么没回」会说明原因。
  - `/status` 显示关键字、runbook 和今天回答、跳过、取材料失败的条数。
- **少 @ 一次**：见上文。
- **自然语言定时与持续委托**：
  - `@机器人 提醒我明天下午 17:00 提交发布单。`
  - `@机器人 每个工作日 18:00 汇总今天群内的开发进展并发在群里。`
  - `@机器人 每半小时看一下这个 PR，一直跟到合并，周五 18:00 前没合就别跟了。`：Agent 用 `schedule create --until 'PR 已合并' --deadline <北京时间>` 建计划，确认卡上写明「直到」和「截止」；达成后 Agent 用 stop-self 停用，到截止仍未完成则自动停用并在原话题说明。见 [Web 控制台的定时任务](web-console.md#5-通用定时任务)。
- **分层协作（Leader-Worker）**：接待的 Agent 整理任务简报交给 Leader；Leader 拆只读方案并指派 Worker 改代码，最终由 Leader 验收回传原话题。前提：开启群工具；Leader 若是终端模式 Agent，机器人和该 Agent 都要是 `full-trust`，否则保存配置时会报错。

---

机器人设置里的「忙时先判断」（`busyTriage`）默认关闭；也可用 `dutydeck settings bot set <App ID> busyTriage=true` 打开。关闭时，执行中收到的普通消息仍照常排队。打开后，问进度由宿主直接回复阶段、最近一步、已用时间、排队数和待审批情况；补充当前任务会尝试插进支持插话的 ACP Agent，终端 Agent 仍排队；机器人管理操作复用 `dutydeck agent` 的校验和权限，只读立即回复，会改东西的先发确认卡，点确认才执行。回复会用一句短话标出理解结果。确认卡或回执发送失败、停止、拿不准、模型报错或超过 15 秒都照常排队，不自动中断。控制短语、斜杠命令、回复待处理卡片和机器人或自动化消息保持原路径。

判断复用「群判定 Agent / 模型」：优先 `decisionAgentId` / `decisionModel`，留空沿用记忆 Agent / 模型，再回落默认 Agent / 模型；可把群判定模型设成便宜、快速的模型。分类器可选 `dutydeck agent` 的查看和控制命令，也可处理「每天九点看下 CI」「以后默认用 codex」这类定时任务和机器人设置请求：定时任务立即发启用卡，草稿保持停用；设置立即发管理员确认卡，确认前不保存。两类卡都回复在当前这条消息下，使用这条消息发送人的身份，不占排队轮次。进度耗时按秒、分秒或小时分显示，例如「12 分 30 秒」「1 小时 5 分」。

## 4. 接入飞书机器人

### 方式 A：Web 控制台一键创建（推荐）
1. 打开 Web 控制台（`http://127.0.0.1:4310`），首次使用点首屏的 **「绑定飞书 Bot」**（已有机器人时这里是「管理飞书 Bot」）。
2. 在弹出的向导里选 **「新增机器人」**，找到 **「一键创建飞书机器人」**，填名称，点 **「创建机器人」**。
3. 系统复用本机已有的飞书开发者登录态（或引导扫码），通过开放平台自动创建应用、配置事件订阅与权限、发布版本并保存密钥。
4. 选择默认 Agent 和工作目录，开启监听。

创建过程中关闭弹窗后，在同一浏览器标签页、同一实例里重新打开「新增机器人」可继续查看进度；切到其他实例不会带出这次创建。「重新连接」只查询进度，不会重新发起创建。当前实例查不到这次创建时，可以点「重新提交本次创建」（沿用同一请求编号，避免同一实例重复创建），或「放弃此记录」（只清除本页记录，不取消已开始的创建）；旧版页面留下、当前实例又查不到的记录只能放弃，请到发起它的实例查看进度。

### 方式 B：CLI 接入
```bash
# 创建并接入新机器人（默认逐项审批 ask）
dutydeck lark create "研发助手" --agent ccflash --listen

# Agent 不支持飞书逐项审批时，必须显式 --full-trust，否则在扫码前就报错
dutydeck lark create "研发助手" --agent <终端模式 Agent 的 id> --full-trust --listen

# 绑定已有自建应用（Secret 从管道读）
printf %s "$LARK_SECRET" | dutydeck setup --lark-app-id cli_xxxxxxxx --lark-app-secret-fd 0 --agent claude --yes
```

“支持飞书逐项审批”的 Agent：ACP Agent（基于成功的 ACP 协议握手，不依赖可选的模型枚举元数据），以及 Claude Code / Seed / Relay 终端模式（经 PermissionRequest hook）。其它终端模式 CLI 只能用 `full-trust`。

**按权重分流 Agent。** 在机器人设置的「Agent 分流权重」中为参与的 Agent 填正数，留空表示不参与；全部留空关闭分流。例如 Codex 填 30、ccflash 填 70，新飞书主会话约按 30% / 70% 概率选择，短期数量不保证精确比例。已有会话保持原 Agent，修改或关闭分流不打断续聊；群固定 Agent、`/new --agent` 及显式模型/推理参数优先。默认模型和推理强度仅用于默认 Agent，其他 Agent 使用各自默认值；记忆与群判定不参与分流。所有候选都需支持当前审批模式，强制拦截会检查并安装全部候选的 Hook。CLI 使用同一设置：

```bash
dutydeck settings bot set cli_xxx 'defaultAgentWeights=[{"agentId":"codex","weight":30},{"agentId":"ccflash","weight":70}]'
dutydeck settings bot set cli_xxx 'defaultAgentWeights=[]' # 关闭分流
```

**兜底 Agent。** 在机器人默认设置或接入向导中选择「兜底 Agent」。机器人使用 `ask` / `approve-reads` 且需要 Codex 兜底时，选「Codex (ACP)」（`codex-acp`）；`codex` 和 `codex-cli` 继续默认使用终端模式。也可通过 CLI 配置：

```bash
dutydeck settings bot set cli_xxx defaultAgentId=ccflash fallbackAgentId=codex-acp fallbackModel=gpt-6.1-sol
dutydeck settings bot set cli_xxx 'fallbackModel=' # 恢复兜底 Agent 默认模型
dutydeck settings bot set cli_xxx 'fallbackAgentId=' # 关闭兜底并清除兜底模型
```

主 Agent 无法启动、未登录、凭据失效，或返回明确的限流、额度耗尽、上游不可用错误时，当前请求最多自动切换一次。只有本轮尚无正文、思考、工具调用或审批请求时才会切换；普通任务失败、取消、权限拒绝和结果未知不会自动重放。有其他排队或运行任务时保留原会话，避免丢失请求。「兜底模型」仅作用于这个机器人自动切换时的新会话；留空使用兜底 Agent 默认模型，推理强度始终使用兜底 Agent 默认值。更换或关闭兜底 Agent 会清除旧兜底模型；手动选择或按权重选中同一个 Agent 时不使用兜底模型。兜底沿用机器人的审批与风险控制；强制拦截会检查、安装兜底 Agent 的 Hook。切换时在卡片说明原因，并开启新会话，携带交接材料作为背景，完整原生对话历史不会跨 Agent 迁移。已有兜底会话继续沿用；新对话重新优先选择主 Agent。显式 `/new --agent`、模型或推理参数不启用自动兜底。

### Claude Code 自定义网关与 API Key

注册第二步选择 Claude Code，展开「模型服务配置」，填写网关 URL、认证方式和 API Key，先点「保存模型配置」，再点「完成配置」。已有机器人可在默认执行设置里修改；网关模型 ID 填在「默认模型」。支持内置 Claude Code 和 `adapterId` 为 `claude` / `claude-code` 的自定义 Agent（如 ccflash），网关须兼容 Anthropic Messages API。

```bash
# 已绑定的机器人：网关密钥从管道读，不进入命令行参数
printf %s "$MODEL_API_KEY" | dutydeck settings agent set claude --app cli_xxx baseUrl=https://gateway.example authMode=bearer --api-key-fd 0
dutydeck settings bot set cli_xxx defaultAgentId=claude defaultModel=your-model-id
dutydeck settings agent show claude --app cli_xxx
dutydeck settings agent set claude --app cli_xxx clearApiKey=true
```

`bearer` 使用 Authorization Bearer，`api-key` 使用 X-Api-Key。配置按机器人和 Agent 独立保存；不带 `--app` 修改的是共享 Agent 配置。URL 需配置该作用域的 API Key 才启用；清除机器人密钥后恢复共享 Agent / CLI 连接配置。密钥保存在本机私有密钥文件中，不在 API 和 CLI 输出里回显。模型用机器人 `defaultModel`，会话明确选择的模型优先；这些设置不改变其他机器人的模型。网关设置在下次启动 Agent 进程时生效，正在运行的会话用 `/new` 重新创建。

### Codex profile

Codex 终端 Agent 可从本机 `config.toml` 选择命名 profile；Dashboard 只读取并展示 profile 名称，模型和凭据不会返回。profile 只对新建会话生效，也可用 CLI 设置共享 Agent：

```bash
dutydeck settings agent set codex codexProfile=review.safe
dutydeck settings agent show codex
```

## 确认卡、消息去向、事项与提示词版本

群参与由模型推断需要主动执行时，会先发送「交给我处理」确认卡；有任务创建权限的人确认后，以确认人的身份执行，24 小时内无人确认就不执行。显式 @、话题续接、主动回复和管理员配置的 direct 场景包保持原行为。网页结果检视可查看各轮授权依据、确认人和判断记录。
消息去向：机器人页面的“最近没处理的消息”可查看 24 小时、7 天或 30 天内的原因。用 `dutydeck lark why <message_id> [--app <appId>]` 查询单条消息，或 `dutydeck lark ignored --chat <chat_id> [--since 24h|7d|30d]` 列表查询。忽略记录保留 30 天。每个机器人下，其他机器人发的消息和真人消息分开计数，各自另有 60,000 条的安全上限（约是单个机器人 30 天消息量的峰值），刷屏的告警卡片不会挤掉真人消息的记录。其他机器人的消息被忽略 1 小时后只留去向和前 160 字的摘要，不再保存卡片正文；升级前已有的记录保持原样，到期后删除。旧记录显示未记录原因。
事项把同一件事的交接、分身、恢复、重试和定时执行串起来；任务列表按事项归并，可展开查看会话和计划。普通 `/new` 开新事项，`/new --handoff` 沿用原事项。修改计划先用 `dutydeck agent schedules` 查编号，再用 `dutydeck agent schedule update <编号>` 更新时间或内容，启停用 `schedule enable/disable <编号>`，保留计划编号；同事项已有生效循环计划时，确需另建才加 `--additional`。原会话不可用时，未受理的下次定时执行改用新会话。

事项内最近一轮仍在等你决定或受阻时，事项继续显示在“待你处理”，完成执行不会掩盖该报告。模型主动执行的确认卡发出后，消息去向显示“等待你确认是否执行”；确认并受理任务后显示已处理，保留判断记录作为授权依据。

机器人预注入提示词每次变更都会保存不可变版本，启动时自动回填已有非空提示词。机器人设置中的“历史版本”可查看全文、按行比较和确认回退；回退会新增版本，过期编辑会拒绝保存。CLI 使用 `dutydeck settings bot prompt-history <appId>`、`prompt-show <appId> <version>`、`prompt-diff <appId> <a> <b>`、`prompt-rollback <appId> <version>`。每轮使用的提示词版本和群长期指令修订号保存在任务外的版本使用记录中。启动回填、读取或冻结版本失败只告警，不影响服务启动和新任务派发；未知版本显示为“未记录版本”，成功记录后清理准备快照。

确认卡绑定发出时的请求正文、附件引用和消息路由；原消息修改后旧卡失效，提示“原消息已修改，请重新确认”，需要重新发送请求再确认。确认仍按点击人的当前权限执行，合法请求只受理一次。

收尾报告和消息去向是任务外的留痕；读取或清理故障会告警，任务受理、调度和结算继续。事项查询失败时，定时计划仍按来源可用性及原执行快照处理；授权、受理幂等与结果未知门禁保持有效。
