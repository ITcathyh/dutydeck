# Web 工作台与自动化闭环 <a id="web-console"></a>

> [← 返回 README](../../README.md) · [全部文档](../../README.md#docs) · [English](../en/web-console.md)

实时连接与记录追平分别显示：连接后可能仍在补齐，首次校准失败后最多自动退避重试 5 次；仍失败时可在状态旁点「重试同步」。追平成功才显示「实时同步」。打开长历史时，旧的已结束轮次先显示摘要，点击「展开完整记录」读取完整事件；无法可靠匹配指令的准备失败及其后记录保守保留原始事件。工作台先只读最近 50 轮的摘要和每一轮的位置（指令前 40 字），更早的轮次滚到或从「跳到轮次」选中时，按 50 轮一页读取摘要，读取期间先显示该轮指令。位置清单仍随轮数增长。「跳到轮次」的选项在点开时才生成，轮次很多时首次点开要稍等。原始日志打开后继续实时更新；复制和导出各自读取点击时固定水位的完整快照，「刷新完整记录」可读取新水位。历史中的原生命令菜单仍可用。

ACP 的图片和资源等结构化内容会保留并展示；支持的内嵌图片可预览，未知或超限的非文本内容显示占位。非文本内容有大小和数量预算；旧的长纯文本保持完整，不额外复制保存为 parts。结果面板按轮列出有来源的产物引用，长会话先检查最近 50 轮，点「检查更早的轮次」再按页读取更早的轮次；引用本身不授予下载权限，也不会自动读取 URI 指向的文件或网页。工作台和分享页里 Markdown 写的图片（`![说明](地址)`）不会自动加载：http(s) 地址显示为「图片：说明」链接，点击后在新窗口打开，其他地址只显示文字；页面的内容安全策略也只允许加载本站、`data:` 和 `blob:` 图片。

在「结果检视 → 每轮产物引用」展开轮次后，可对已登记的本地文件点击「保存当前文件快照」，再「查看快照文本」或「下载已保存快照」。快照保存的是点击时的内容，显示时间、大小和 SHA-256，不证明原轮次当时的文件内容；后续修改源文件不会改变旧快照。只接受当前会话工作目录内的普通文件（最多 20 MiB），凭据、实例内部数据、符号链接、硬链接和特殊文件被拒绝，不获取远程 URL。安全校验目前仅支持 Linux。文本预览最多 16,384 字符，HTML/SVG 也只显示转义文本。列表、保存、预览和下载均需安装管理员及原会话查看权限，分享链接和任务工具凭据不授予此权限。

## 1. 工作台、全部任务与任务详情
- **工作台**集中展示需要决定、需要恢复和正在推进的任务；**全部任务**用于搜索和项目筛选，列表筛选不隐藏侧栏中的当前任务；**自动化**管理真实任务计划。暖白和深色主题使用同一套状态语义，侧栏可收起并调整宽度。
- **上下文占用徽标**：侧栏任务行在最近一次上下文占用达到 80% 时显示橙色小徽标（如 `82%`），悬停和读屏均说明「上下文已用 82%」；低于 80%、Agent 没有上报占用或容量未知时不显示。数据由 `GET /api/sessions/summaries` 的 `context` 字段带出：服务端用一次查询取出全部会话最近一条用量事件，整体缓存 30 秒；只读已有事件，不读原生日志，不新增存储。随任务列表每 15 秒刷新；当前任务的精确占用仍看任务顶部的用量面板。
- **目标步骤耗时**：展开的目标里，每个步骤在最近一次尝试上显示耗时。已结束（完成、失败、中断、取消）的尝试显示「用时 2 分 30 秒」，执行端已接收、仍在运行的显示「已运行 5 分钟」，不足 1 秒显示「<1 秒」。时间优先取该尝试任务的创建到最后更新时间（读取任务列表接口，不含准备阶段，也不受之后补写的评审证据影响）；读不到任务记录或任务还没结束时，退回尝试自己的时间戳并标「约」，如「用时 约 2 分钟」。已结束尝试的任务尚未结束时每 5 秒补读一次，结束后停止。「已运行」随目标数据刷新（每 5 秒轮询，数据没有变化时不重绘，读数可能略滞后）。展开步骤后每次尝试各带自己的耗时；没有尝试、准备中或需要处理的尝试不显示。
- **待你决定**：工作台顶部把所有等你点按钮的事集中成一个列表，按类型分组，每项写明所属任务、已等待多久和可执行的动作：权限审批、Agent 提问、结果未知待核对、等你决定的收尾报告、先出计划的计划卡、工作项待确认 / 待回答 / 步骤请求、工作项等你确认的计划修订（目标保持原状态，条目写明修订版本、内容摘要前 8 位和影响的步骤数）、PR 确认清单与评审意见、飞书结果验收卡。能在 Web 上决定的项（批准 / 拒绝权限、批准 / 取消计划、确认 / 取消工作项、确认 / 放弃计划修订、确认 PR 推送）直接调用原有接口，其余项点「查看」进入原任务；拒绝权限时可点「拒绝并说明」填写原因（最多 1000 字），与任务里审批卡的「拒绝并说明」相同：原因记录在审批历史，终端模式的 Agent 会收到原因，ACP 模式的 Agent 只知道被拒绝，直接点「拒绝」则不带原因；只能在飞书卡片上决定的项（飞书会话的计划卡、结果验收、PR 评审意见）只展示，并注明请在飞书处理。批量只开放给不会开始执行、也不需要先看内容的决定：拒绝权限审批，以及放弃计划修订；批准权限、批准计划、确认推送并开 PR、确认工作项（含确认计划修订）一点就会执行，只能逐项处理，PR 条目列出改动文件，计划点「查看计划」回原任务查看。批量拒绝不附原因，需要说明时逐项「拒绝并说明」。勾选同类项后确认，前端逐项调用原接口，每项单独显示成功、已失效或失败，没有新的后端批量语义；混选不同类型不提供批量。条目沿用各对象自己的校验拒绝过期决定：权限已被处理、计划已不是最新或已决定、工作项版本已变、修订已不在待确认或已被 Agent 换成新内容（摘要不一致），会显示「已失效」，不会套用到新状态。列表由 `GET /api/inbox` 只读汇总，不新建存储，权限沿用各任务的查看权限，分享链接读不到。权限审批已逐条列出的任务不再在下方「需要你处理」里重复。
- **命令面板**：按 `Ctrl-K`（macOS 为 `Cmd-K`）搜索入口，或输入“Bot 名称 回复方式”“Bot 名称 免打扰时段”定位具体设置。结果显示 Bot 名称、App ID 和作用范围，同名 Bot 可用 App ID 区分；选择后展开对应页面并定位字段。也可搜索终端后端和模型服务设置；跳转沿用未保存内容保护及浏览器前进、后退。
- **输入草稿**按实例和任务保存在当前浏览器，包含正文、文件 / Skill 引用、发送方式与先出计划选项，切任务、打开设置和刷新后可恢复；存储不可用时仅保留在当前页面内。发送失败保留草稿，成功回执只清除被确认的发送版本，期间继续编辑的新内容会保留；不会自动重发。新建任务表单关闭后也保留填写内容和失败重试状态，但这份创建草稿只在当前页面生命周期内保留，刷新清除。
- **任务内容**分为「对话」「改动」与仅 PTY 连接可用的「终端」；「结果检视」展示改动、验证证据、PR 与投递记录，执行环境和任务自动化折叠在下方。完成本轮、验证通过和 PR 状态分别展示。
- **会话追踪**：在任务顶部点「追踪」，查看会话元信息、已加载序列范围、分类计数和事件时间轴；打开时读取完整历史快照，并接续实时事件。可搜索摘要、类型或 ID，按分类筛选、切换排序、按轮次分组并展开原事件数据。表格和时间轴每页最多 100 条；筛选覆盖全部已加载事件，时间轴只绘制当前页。读取中或失败时明确标注部分记录并可重试。时长只展示工具已记录或按同一任务、执行尝试和调用 ID 配对的观测区间，未知显示 `—`；消息不推算模型执行时长，当前模型配置不作为历史模型证据。
- **阅读连续性**：每项任务的阅读位置、跟随最新状态以及过程 / 工具展开选择，按实例和任务保存在当前标签页的 `sessionStorage`；切任务、设置和刷新后恢复。主题、侧栏布局、任务标签与检视偏好保存在当前浏览器，均不跨设备同步。
- **设置与接入**按个人界面、本任务、机器人 / 群聊和实例接入说明作用范围；模型与推理等高级创建选项保持折叠，Web 创建仍默认独立 Git 工作目录，完全信任仍需明确确认。
- **共享 Agent 模型配置草稿**未保存时，切换设置分区、关闭或跳转前会要求确认，刷新或离开页面由浏览器提醒。取消离开与保存失败都保留输入；保存期间暂时禁止离开。草稿只留在当前页面内，API Key 不写入浏览器存储。
- 任务按 **「待处理」**（等审批 / 待回答）、**「进行中」**、**「已完成」**、**「已归档」** 分层。
- 卡片显示耗时、工具调用明细和最终产物。
- 会话首次加载期间收到任务变化时，会在当前读取完成后补取完整任务状态，更新完成状态和结果未知任务的恢复操作。
- 当前任务的标题和摘要以已加载的执行记录为准，不会被滞后的任务列表刷新覆盖；迟到的发送确认不会覆盖已加载的完成结果；再次选择当前任务会保留未发送的输入。创建任务或准备定时任务提交期间，目录与 Agent 等配置、关闭和取消入口暂时禁用，Agent 列表刷新也不会解除关闭限制。创建失败后可修改配置并重试；首条指令发送失败时，重试会复用已创建的会话。
- **终端回放只有终端模式（`pty-cli`）Agent 才有**，最多保留 5000 行；ACP Agent 没有终端。原始日志里的终端画面每轮只保留最近 50 屏的内容，更早的帧保留记录但内容清空。
- 终端分别显示初始化、连接中和已连接等待输出；空快照不会判为故障。握手超过 10 秒会自动重连，等待期间保留已收到的画面；只读终端不发送输入或调整远端尺寸。
- 支持新指令排队，也可以「立即中断」抢占。
- 本机所有者可取消、停止旧式飞书会话中的任务，仍需通过执行状态与权限检查。
- 中断任务会取消这一轮的待回答提问，正在校验的提问也不会随后弹出；迟到回答会被拒绝。会话空闲时仍可正常提问。
- 原生后台子任务独立显示数量和生命周期；主回合结束但仍有后台任务时显示「主回合已结束 · 后台子任务运行中（N）」，不把晚到通知当作新回答。
- 会话流会自动恢复静默断流；标签页进入后台 60 秒后释放连接，回到前台重新连接并校准事件、任务和会话状态。已观测到批量缓冲的连接不按静默判死；这些行为不需要新设置。
- `/sessions/<会话 ID>?panel=workspace` 可直接打开既有工作目录面板，包括归档会话；沿用登录门禁，链接本身不触发清理预检或删除。
- 飞书卡片打开的只读任务详情显示来源话题、来源群聊（私聊显示来源聊天）和最初发起人，可跳回已知话题或聊天；未记录的话题和缺失的历史来源记录会明确标注，名称读取失败时显示已有 ID。分享页先给结论：顶部是提问、状态和起止时间（按浏览器所在时区），结论卡把首段放大成导语，表格在手机上每行变成一张小卡（标题与数值在第一行，其余列带表头标签）；「复制结论」生成可直接贴回飞书的纯文本并附本页链接。执行过程默认收成一行概要和一条按时间分桶的调用分布图（两端标起止时刻；执行中最后一个有调用的时间段会发光，发光圆点标出此刻，右端不写时刻；旧记录不显示），展开后是完整记录；只有一轮更早的提问时直接显示一行，两轮及以上合并成「更早 N 轮」，点开逐轮查看。执行中显示正在做的步骤，失败时显示原因。页面随窗口宽度展开，左右边距与页头一致；宽屏右侧固定显示来源、这次执行的用时与调用次数和操作按钮，窄屏保留阅读边距，来源变成两个链接。

### 配置来源与记忆管理 <a id="configuration-and-memory"></a>

任务详情的「配置来源」只读显示已保存的 Agent / 机器人默认、群解析结果和当前会话；选择「历史任务」「执行尝试」可查看任务接受时的执行选项、技能交付摘要和已有插件动作账本。新保存的模型不会被用来补历史。没有留存的字段显示 `unknown`，原生 CLI 自行加载的 MCP / Skills / 私有配置显示 `unverified`；不扫描秘密文件，不展示环境变量、密钥或工具正文。插件设置中的「解释已保存配置」按字段展示来源；工具仍在每次调用时重新解析绑定和授权。

「管理记忆」在飞书会话中对应实际机器人共享群池、当前群或当前私聊，可搜索、替换式修订和删除；修订冲突会保留草稿并要求重新加载。来源会话不可访问时只显示受限说明。已保存与已注入分开展示：最多保留最近 20 轮关联、100 个删除记录，Web 最多显示 10 轮，不能还原历史完整提示词。

普通 Web 会话可在同一入口创建项目记忆，选择项目后点击「绑定所选项目」，其他会话须逐个显式绑定同一项目 ID 才共享。目录、视觉分组、同路径新会话或 worktree 都不自动继承；飞书和受管工作事项会话不能加入。管理需安装管理员权限，绑定还需该会话权限。每个新轮次重新读取项目开关和绑定，按 3000 字符条目预算注入；关闭或解绑从下一轮停止提供，已发送的上下文无法撤回。项目最多 200 个有效条目、12 个主题、100 个删除记录，单条 1000 字符，凭据和注入指令拒绝保存；不自动提取项目记忆，也不提供 Agent 写入接口。

```bash
dutydeck settings explain --session ses_xxx --task task_xxx --attempt attempt_xxx
dutydeck memory manage pool-list --session ses_lark --query '部署'
dutydeck memory manage pool-revise mem_xxx --session ses_lark --content '修正后的事实' --expected-fingerprint <读取时的fingerprint>
dutydeck memory manage project-create --name '项目名称'
dutydeck memory manage project-show --project proj_xxx
dutydeck memory manage project-add --project proj_xxx --content '项目事实' --expected-fingerprint <读取时的fingerprint>
dutydeck memory manage project-bind --session ses_web --project proj_xxx
dutydeck memory manage project-enable --project proj_xxx --enabled false
dutydeck memory manage project-unbind --session ses_web
```

这些是管理员管理命令。`settings explain` 沿用 `settings --instance` 选实例；显式指定本机地址时，这些命令均须同时提供 `--url http://127.0.0.1:<port> --database /path/to/dutydeck.db`。`--attempt` 必须与 `--task` 一起使用；记忆修订与添加使用读取时返回的 fingerprint 拒绝过期修改。

### 目标计划修订 <a id="work-plan-revision"></a>

任务详情的「目标」面板可修改未结束目标（待确认、执行中、等待回答或失败）的计划：在「修改计划」里编辑完整计划 JSON（格式同创建时的 `plan`），点「预览影响」查看哪些步骤保留结果、作废重跑、先停止、删除或新增，再点「提交修订」。预览和提交绑定同一修订号，目标在此期间有任何变化都会拒绝提交，需重新预览。需要的权限与取消、重试该目标相同；新换上的 Agent 按创建时的规则授权。

- **影响范围**：新增步骤、内容有变化的步骤（指令、标题、Agent、依赖、条件、工作区、Skill、审查策略），以及它们的全部下游，都会作废已有结果并重跑；其余已完成的步骤保留结果，不再执行。
- **停止运行中的步骤**：受影响或被删除的运行中步骤先用取消时的停止流程停下。任何一个无法证明已停止，整次修订失败，计划保持原版本。已停止的那次执行结果未知：在它的执行记录里按「结果未知」核对处理（标为失败或已完成）之前，这一步保持「待执行」，同一工作区里的其他新步骤也会等待；核对后才重跑。修订不会把它当作没执行过而直接重发。
- **结果未知或已结束的目标不能修订**：需要处理的目标先按原恢复流程核对；已完成、已取消的目标不再修改。
- **Agent 提交的修订**：Agent 只能收窄计划（改未失败步骤的标题或指令、删除不带审查策略的 Agent 步骤、增加依赖、减少 Skill）。新增步骤或 Agent、换 Agent、加 Skill、改工作区、条件或审查策略、去掉依赖、删除人工等待或带审查策略的步骤、更换最终输出步骤、让已失败的步骤重跑（直接改它或改它的上游都算），或者目标创建时就要求确认（如群聊），修订都记为「待确认修订」：面板和飞书卡片列出原因、影响和内容摘要（前 12 位），点「确认修订」后才停止并生效，「放弃修订」按原计划继续。待确认期间目标状态不变，计划停在当前版本，运行中的步骤照常收结果，后续步骤照常按当前计划派发；目标完成或取消时待确认修订随之作废。Agent 再次提交会替换待确认内容，摘要随之变化，飞书推出新卡；按旧卡或旧摘要确认会被拒绝。影响里另列「作废已完成结果」。确认时按当时的步骤状态重算影响：出现卡片上没写过的要停止或要作废结果的步骤（例如提交时某步还没开始、等待期间开始运行了），这次确认被拒绝；同一步骤从「先停止」变成「作废已完成结果」不算新情况。被拒绝时待确认修订改为最新影响并换摘要，飞书推出新卡，核对后再确认。目标阻塞时修订无法确认，只能放弃。待确认期间不能单独重试失败步骤，先确认或放弃修订；失败但带待确认修订的目标，插件触发器按仍在进行计、占着并发名额，失败后才收到修订的也会重新占回（限触发后 24 小时内的运行记录）；定时计划只检查最近一次启动的工作项，它失败且带待确认修订时跳过下一次启动，更早启动的工作项不再检查。
- **次数上限**：被 Agent 提交的修订（包括经人确认的）作废的尝试，仍计入单步最多 3 次尝试和审查返工轮数；只有人自己提交的修订会让这些次数重新计算。
- **版本历史**：每次生效的计划都保留为新版本（版本号递增），记录来源（创建、人工修改、Agent 修改）、提交或确认的人（目标创建人或安装管理员）、时间、原因和影响。被删除步骤的执行记录仍可查看。服务在修订过程中重启时，目标要么完全是旧计划，要么完全是新计划。

## 2. 验证与返修
- 验证门禁目前只对**飞书任务**生效，需要先给机器人配验证命令（`pnpm test`、`go test ./...` 等）。
- 任务改了代码后，服务端在工作区执行验证。结果卡显示「验证通过」「验证未通过」「验证已过期」或「未验证」。
- 失败时，截断后的报错作为下一轮返修提示发回 Agent，最多 2 轮。
- 验证开始前会检查：本会话上一轮的执行结果未知（需先在恢复入口核对），本会话仍有原生后台任务，或同一目录（实际路径相同或互相包含）里另一会话还有未结束的执行、原生后台任务或验证时，不执行验证，接口返回 409 `SESSION_BUSY`。同一目录同时只运行一个验证，其他请求可在它结束后重试。飞书自动验证等约 5 秒仍忙就跳过，结果卡显示「未验证」并说明原因，不发回返修；常驻的后台开发服务器也算占用，需要结束后再手动验证。验证运行期间，同一 Git 仓库里其他会话的新任务先排队，验证结束（包括失败、超时、被停止）后可以开工。
- 仓库里有未拉取的子模块（如没加 `--recursive` 的普通克隆、`git submodule deinit` 之后、独立 worktree）也能验证：代码指纹按主仓库记录的子模块提交计算，已拉取的子模块仍检查其中的改动。
- 「结果检视」里的验证记录：有验证正在运行时每 5 秒刷新一次；没有时每 60 秒刷新一次，切回窗口或页面重新可见时立即刷新。所以代码改动后，「代码已变化」最多延迟 60 秒才出现。

## 3. 手机看改动
- 飞书结果卡的「改动 N 个文件 +A −D · 查看改动」链接 14 天有效，只能看这一轮的改动。
- 只有在 git 仓库里、由 runtime 正常执行的轮次才记录改动。文件与符号链接互换时，差异仍归属正确文件。仓库里没被忽略的未跟踪文件太多（单个超过 20 MiB、合计超过 50 MiB 或超过 2000 个）时不记录，结果卡上没有改动行，服务日志写原因——建议把大文件和构建目录加进 `.gitignore`。
- 「查看改动」页可以逐行评论：登录 Web 的用户提交后直接发给 Agent；只有分享链接的人提交后，会在飞书原话题出一张确认卡，有权限的人点「交给 Agent 修改」才会执行。提交期间新增或修改的评论草稿会保留。
- 「查看改动」页按“源码、测试、文档”的顺序排文件，并在补丁总量（1 MiB）用完时先省略靠后的文档和测试，而不是源码。锁文件（固定名单：`package-lock.json`、`npm-shrinkwrap.json`、`yarn.lock`、`pnpm-lock.yaml`、`bun.lock`、`bun.lockb`、`deno.lock`、`Cargo.lock`、`go.sum`、`poetry.lock`、`uv.lock`、`Pipfile.lock`、`composer.lock`、`Gemfile.lock`、`Podfile.lock`、`pubspec.lock`、`flake.lock`、`packages.lock.json`、`gradle.lockfile`）和仓库 `.gitattributes` 里标了 `linguist-generated` 的文件默认折叠：排在最后，只显示增删行数和“已折叠”说明，不读正文、不占用 1 MiB 预算；点「展开查看」才按需读取这个文件（单个文件最多 1 MiB，超过只提示改动太大）。展开后的行不能逐行评论。不按路径猜生成物，`dist/`、`.min.js` 没有 `.gitattributes` 标记就照常显示。飞书结果卡只有改动摘要行，不受影响。
- 轮换分享密钥 `dutydeck auth share-key rotate` 后，已发出的链接全部失效。

## 4. 用量与成本
Web 侧栏「用量与成本」有「费用」「明细」「会话分析」三个标签；飞书里 `/status` 显示本月用量。
- 会话用量浮层在服务端同时提供未缓存输入和缓存读 token 时显示缓存命中率；缺少任一项时不显示推算值。

- **会话洞察分析器**：随 npm 包内置，构建服务时自动生成；使用 Dutydeck 当前的 Node.js 运行时，在隔离子进程中本地分析，无需 Go 编译器、外部分析器二进制或单独构建引擎。源码开发使用工作区的 `tsx` loader。指标版本升级为 `v2`：旧快照仍可读取，不同指标版本不混算差值或分组汇总；重新分析可统一版本。Codex 同一原生输入只计一轮；fork 继承历史不计入独立会话汇总；已计价记录的金额和时间保留在洞察与导出中。刷新生成修正后的快照，已有快照保持不变。洞察刷新不会修改任务用量与计费记录。快照是否过期的判断在 15 秒内复用，刷新排队或进行中时不再重新判断，因此仓库或任务变化最多延迟 15 秒才标为过期。

- **月度上限**：美元，按机器人或按群设置。Web，或 `dutydeck settings usage set-cap <月度美元> --app <appId> [--chat <chatId>]`。
- **价格表**：内置表含 OpenAI 和 Claude 型号，按模型名最长前缀匹配；匹配不到的型号记为“未定价”，不会套默认价。用 `DUTYDECK_USAGE_PRICING_JSON` 可整表覆盖；只缺个别型号时用 `DUTYDECK_USAGE_PRICING_EXTRA_JSON` 按型号叠加单价（格式见 [agents.md](agents.md) 环境变量表）。设置后这些型号的花费开始计入月度上限，已设上限的实例可能比以前更早被拦；变量写错时服务起不来，`dutydeck doctor` 会报出是哪个变量无效。Claude 型号只认日期后缀（`-YYYYMMDD`）和 `-latest`，所以 `claude-opus-5-6` 不会落到 `claude-opus-5` 的价格上。
- **用量型号**：依次取 Agent 读数、任务、会话、Agent 配置里的型号；都没有时采用 ACP Agent 自己报告的当前型号（去掉 `[推理强度]` 后缀，如 Codex），来源记为 `runtime`。
- **用量来源**：ACP Agent 报多少算多少，不报成本的按价格表估算。终端模式 Claude 的用量来自 transcript，是估算；子代理用量来自 `<session>/subagents/` 下的文件。同一轮多个型号时各自按自己的单价算，任一型号没有单价，整轮记为未定价。终端模式 Codex 按轮记 token：取会话日志里每次模型回复的用量（旧版 Codex 日志没有逐次记录时，对累计值做差），resume、fork 和 daemon 重启后重读都不重复计；型号取日志里的实际型号，没有单价的只记 token。这部分金额出现在用量报表里，标为“不计入上限”，月度上限、75%/95% 提醒和 `/status` 的已用比例不算它（按“无用量数据”计）。Traex 终端模式没有用量。
- **“部分用量未知，上限可能不准”**：任一轮的用量读不到时出现，位置是 Web 上限卡片、拒绝说明和告警。什么算未知：子代理文件读不到或格式不认识、daemon 重启后恢复的那一轮、未定价的型号。
- **没有计入的加价项**：美国境内推理 1.1 倍、快速模式、Batch、1 小时缓存写、Haiku 5.5 的分档价（Haiku 5.5 记为未定价）。所以估算偏低，不是账单。
- **接口**：`GET /api/usage/report`、`GET /api/usage/tasks`，参数 `from`、`to`、`model`、`agentId`、`appId`、`origin`（`/api/usage/tasks` 另有 `limit`、`offset`）。日期按 daemon 本地时区。需要安装管理员权限。

## 5. 通用定时任务

在 Web「自动化」中点「创建定时任务」，选择 Agent、目录和权限后保存计划；保存不发送执行指令，新计划默认停用。也可在已有任务「结果检视 → 任务自动化」中创建。启用前需核对完整指令、执行模式、目录、时区、补跑策略和服务端保存的投递位置（Web 来源任务，或飞书机器人、群与回复消息 / 话题 ID）；目标无法核实时不能确认启用。停用保留计划与历史，已提交的任务继续收尾。

自动化总览按通用定时计划（接口来源 `engine=session`）分页，可按实例、Agent、名称、启停和健康状态筛选；统计覆盖当前实例内有权访问的全部此类计划，不从当前页推算。协作委托的定时定义不计入这份总览，仍从「群聊管理」进入。跨实例视图只读取已配置代理，分别显示可用、断开、无权限或旧版不支持的范围；部分覆盖不表示未连通实例没有计划。跨主机身份委派和自动接管不在支持范围内。每个计划有独立分页历史，单次运行使用固定地址，展示该次冻结输入、最终输出、执行尝试、阶段时间与投递事实；旧记录缺少的证据明确显示未知，不跳转到最新聊天。Markdown 结果支持 GFM 表格，窄屏在表格区域横向滚动，可复制结果原文。

- **会话模式（`session`）**：默认模式，旧记录未保存模式时也按此处理，沿用来源任务的上下文。停止或归档来源任务会及时停用关联计划并保留原因，仍可停用或删除。
- **每次新会话（`fresh`）**：每次触发新开一个会话，只执行计划指令，不带来源任务的聊天历史，结果仍发回来源任务（飞书的原群或话题）。保存时冻结来源任务的 Agent、目录、模型、推理强度和权限，在来源任务的目录里执行（不另建 worktree），与来源任务同仓库的执行按下方资源协调排队。同一次触发重试、重启或迟到回执都落在按触发编号派生的同一个会话，不会再开第二个。下一次触发时，上一次的执行会话自动归档（只读保留记录）；会话里还有排队、执行中或未结算的任务（例如你在里面追加的对话）时先不归档，等之后的触发再试。保留期间，已排队的任务继续执行，能在计划当前会话里追加消息、取消排队任务的人，在这个旧会话里也能这样做；计划自己的后续触发只在新会话里执行。计划被删除、发起人失去来源任务的权限或旧会话被归档后，尚未开始的任务不再执行，追加消息和取消也会被拒绝，已经开始的那一轮不受影响。最后一次的会话不归档，其终端进程按空闲阈值释放。来源任务停止或归档时计划同样停用。可在编辑中与 `session` 互相切换，有未结束的执行时拒绝切换。
- **独立模式（`independent`）**：仅创建时显式选择，要求 Git 仓库并准备专用受管 worktree；准备失败不会退回共享目录。计划固定 Agent、模型、权限、目录和只含计划指令的上下文（`prompt_only`），复用稳定的专用执行会话。停止来源聊天不停止独立计划，权限撤销仍会阻止后续提交与投递；创建来源、执行位置和交付位置分别保留。旧计划不会自动迁移，模式不能通过编辑切换。
- **资源协调范围**：当前实例数据库中，交互、协作与计划任务在原子准入时共同检查规范化仓库身份；不同 worktree、子目录或符号链接不绕过同仓库限制，非 Git 任务按规范化工作目录协调。未知执行和未安全结束的占用不会因重启或超时自动释放（超过 7 天且执行进程已证明退出的结果未知任务除外，见「结果未知的任务」）；飞书群记忆作业不参与仓库协调。其他独立数据库、旧服务进程和外部工具不受这项协调覆盖。 转交到新会话的请求仍受同一仓库的未知执行与资源阻塞约束；先在原任务详情完成人工核对，确认资源安全后排队请求才会执行。

支持指定时区的一次、每天、每周、固定间隔和五段 Cron。默认补跑策略 `coalesce` 在恢复后合并补一次；`skip` 只在迟到超过正常扫描的宽限时跳过：迟到从发现这个时点的那一轮扫描开始时算，宽限为 60 秒加上一轮扫描的耗时。两种策略都可用 `maxLatenessSeconds` 限制有效期，超过期限的时点不补跑，短于扫描宽限的有效期按宽限计，更新时传 `null` 可清除。策略决定会保留覆盖区间，不创建无限积压。同一计划有未结束或结果待核对的执行时不再启动下一次，补跑策略不能绕过未知结果。运行完成事件会唤醒结算与投递，周期扫描仍用于恢复；阶段时间来自实际记录，缺失时间不以更新时间代替。只改名称会增加修订号，但保留执行代际、到期时间、待执行轮次及原执行身份；改指令、时间或其他执行配置会产生新代际。同一来源任务里未删除的计划名称唯一（停用的也算）：创建或改名撞上已有名称时返回 `SESSION_AUTOMATION_SCHEDULE_NAME_CONFLICT`（409）和已有计划编号，请改用 `update`。飞书里的 `/schedule every` 和结果卡「每天 … 自动执行」遇到同名时同样不新建、不改动，回复中文说明、该计划的启用状态、启停命令，配置了 Web 地址时附编辑链接。旧版本留下的同名重复计划不自动合并，需手动删除多余的。

结果未知时，总览显示阻塞执行及等待时间，从固定运行详情进入原人工核对入口。确认完成、确认失败或明确重试均需权限与审计；人工重试是同一任务的新尝试，原未知尝试与后继结果分别保留，不能自动重发或把最新尝试冒充原结果。协作投递未知会核对已持久化的可信回执，没有可证明的回执时继续保持未知；停用通知先保存发送意图，明确未发送的失败可重试，发送结果未知时不自动重发。

Cron 的日期和星期字段中，只要有一项以 `*` 开头（包括 `*/n`），两项都须匹配；两项都有限定值时，任一匹配即可。例如 `0 9 */2 * 1` 只在每月奇数日且为周一的 09:00 触发。一次性计划拒绝无效日历日期或时间（如 2 月 30 日）；历史无效计划仍可查看和修改，但保持停用，修正后才能启用。没有后续触发时点的计划不能创建或启用：一次性时间已过或落在按策略跳过的夏令时空档，或 cron 永远不匹配（如 `0 0 30 2 *`）。

CLI 使用同一套接口，结果为 JSON：

```bash
# 创建新的来源会话与会话模式计划；不立即执行，默认 shared 目录
dutydeck schedule create --agent codex --cwd /path/to/project --name 日报 --prompt '检查变更并总结' --cron '0 9 * * 1-5' --timezone Asia/Shanghai
# 每次触发新开会话执行，不带聊天历史，结果仍发回来源任务
dutydeck schedule create --session ses_xxx --name 更新并部署 --prompt '拉取最新代码并部署' --cron '0 2 * * *' --timezone Asia/Shanghai --mode fresh
# 已有计划切换为每次新会话（或用 --mode session 切回）
dutydeck schedule update schedule_xxx --session ses_xxx --mode fresh
# 显式创建独立模式：另建专用受管 worktree，只使用计划指令
dutydeck schedule create --agent codex --cwd /path/to/project --name 独立日报 --prompt '检查变更并总结' --cron '0 9 * * 1-5' --timezone Asia/Shanghai --input '{"mode":"independent","misfirePolicy":"coalesce","maxLatenessSeconds":3600}'
# 或为已有任务创建计划：--session ses_xxx --every 30（分钟）或 --at 2026-12-01T09:00
dutydeck schedule list
dutydeck schedule show schedule_xxx --session ses_xxx
dutydeck schedule enable schedule_xxx --session ses_xxx
dutydeck schedule update schedule_xxx --session ses_xxx --prompt '检查构建并总结'
dutydeck schedule disable schedule_xxx --session ses_xxx
dutydeck schedule run schedule_xxx --session ses_xxx --idempotency-key daily-check-1
dutydeck schedule history schedule_xxx --session ses_xxx
dutydeck schedule delete schedule_xxx --session ses_xxx
```

「立即执行」可用于停用的计划，只跳过时间等待，仍检查执行条件与权限，不改变下一次定时；同一个幂等键始终返回原执行，脚本重试应复用 `--idempotency-key`。删除后停止后续触发并使尚未提交的任务失效，已提交的任务继续收尾，历史和结果保留。`history` 返回该计划最近 1000 条记录，按时间从新到旧排列；查询已删除计划的历史请指定 `--session`。`show --session` 可查看删除记录。用 `--input '<JSON>'` 或 `--file plan.json` 设置完整创建参数或更新补丁（含 `condition`、`dstPolicy`、`misfirePolicy`、`maxLatenessSeconds`、`mode`；`--mode` 创建时可选 `session`、`fresh`、`independent`，更新时只能在 `session` 与 `fresh` 之间切换），`--expected-revision` 可拒绝并发修改。`--instance <id>`、`--url`、`--database` 的目标规则与 `dutydeck settings` 相同。创建新会话后若保存失败或响应丢失，CLI 会返回会话 ID；先用 `list --session <id>` 检查是否已经保存，确认不存在后再用该 `--session` 重试。

API：`GET /api/automation/schedules` 支持 `offset/limit/name/sessionId/agentId/enabled/health/sort`，返回此类计划列表、完整授权范围统计与分页信息；`GET /api/sessions/:sessionId/automation/schedules/:id/history?offset=0&limit=20` 按计划分页，未指定分页时保留旧上限；`GET /api/sessions/:sessionId/automation/schedules/:id/runs/:occurrenceId` 读取固定运行详情。所有入口沿用来源任务权限，分享链接不授予全局计划列表访问。编辑使用 `expectedRevision` 拒绝过期修改。

后台任务沿用选定的权限姿态；`ask` 可能等待人工审批，需要无人值守时应显式选择适当权限。计划和执行记录保存在所属运行时的数据库中，每个数据库只允许一个运行时持有执行权；Web 与机器人实例通过实例切换访问各自的计划。

周期任务达到用户设定的停止条件时，Agent 可用 `dutydeck agent --turn "$TURN" schedule stop-self` 请求停用自身计划，不接受计划编号。仅限正在执行的宿主定时触发轮次，手动执行和一次性计划不可用。宿主在本轮成功且结果投递结束后，再核对原执行身份和计划是否仍是原版本，才停用并保留历史，结果投递期间不会开始下一轮；结果卡自动重试用完仍发送失败时照样停用，停用原因写明结果没有送达，并照常发停用告知。任务失败、Agent 收尾报告受阻或等人决定、投递尚未结束、权限撤销或用户修改过计划时不会因此停用。

**一直跟进，直到办完。** 循环计划可选设置完成条件（`completionCondition`，自然语言）和截止时间（`deadlineAt`）：

- 有完成条件时，每次运行在计划指令后附上完成条件和截止时间，告诉 Agent 先核对、确认达成后用上面的 `schedule stop-self` 停用；保存的指令本身不变。stop-self 目前只在飞书来源的会话里提供，其他来源的 Agent 会在结果开头写明「已达成完成条件」，由你停用。
- 到截止时间计划仍启用时，宿主停用计划，停用原因写「已到截止时间 …，未确认完成」，并按停用告知发到回报位置（飞书原话题；Web 任务在计划上显示）。已提交的那一轮照常收尾，但它之后的 stop-self 不再改变结论。截止时间已过不能启用，需改晚或清除。
- 一次性计划不能设完成条件或截止时间。改完成条件或截止时间算执行配置变化，会产生新代际。
- 计划和自动化总览显示跟进状态：正常等待下次运行、本轮执行中、等待人工（本轮有待审批或待回答的提问、结果未知待核对、模板工作项待确认）、最近一轮失败、已完成（stop-self 确认）、已到截止（未确认完成）、已停用。重新启用后清除上一段的完成或截止结论。

**启动工作项模板。** 计划也可以选择「每次启动一个已保存的工作项模板」（`workTemplate: {id, version}`），以计划指令作为工作项目标，按触发编号去重，同一次触发重试拿回同一个工作项。需要确认的计划仍要人工确认，权限沿用模板启动的规则；启动的工作项不归属该任务此刻正在运行的那一轮，不沿用它的风险策略，也不计入它的用量。上一次启动的工作项还没结束时，这次跳过；模板被删或当前身份不可见时，这次记为出错并在回报位置说明，连续三次同因出错自动停用。模板计划只支持沿用当前任务（`session` 模式）、每次到期执行，不支持完成条件，可以设截止时间。

```bash
# 每 30 分钟看一次，直到 PR 合并；12 月 1 日 18:00（计划时区）仍未完成就停用并告知
dutydeck schedule create --session ses_xxx --name 跟 PR --prompt '检查 PR 的 CI 和评审意见并推进' --every 30 --timezone Asia/Shanghai --until 'PR 已合并' --deadline 2026-12-01T18:00
# 每个工作日 9 点启动已保存的工作项模板（编号@版本）
dutydeck schedule create --session ses_xxx --name 发布检查 --prompt '检查今天的发布' --cron '0 9 * * 1-5' --template template_xxx@2
# 清除完成条件、截止时间或模板
dutydeck schedule update schedule_xxx --session ses_xxx --input '{"completionCondition":null,"deadlineAt":null}'
```

**到点先跑前置命令。** 「每次到期执行」的计划可以设一条前置命令（`precondition: {command, timeoutSeconds}`），适合“没有新提交就别叫醒 Agent”这类轮询：

- 到点后、开执行会话或启动工作项模板之前，宿主在计划执行目录（保存时冻结的目录，取真实路径）里用 `/bin/sh` 跑这条命令。退出码 0 才照常执行；非 0 记为「已跳过」，不建任务、不消耗用量、不发通知，也不算一次没做成。超时（默认 15 秒，最长 20 秒）、无法启动或进程没收干净算一次没做成，在回报位置说明，连续三次自动停用。「立即执行」同样先跑前置命令，但不计入连续没做成。命令在后台跑，不耽误其他计划；「立即执行」不等命令结束，先返回待执行，结果随后出现在运行记录里。命令通过后先记下，之后服务重启不会再跑一遍命令，直接接着开会话或启动工作项。
- 命令与交付前验证用同一个执行器：只带 `PATH`、`HOME`、`LANG` 等最小环境变量，不合并 Agent 配置、密钥和群工具令牌；命令在独立进程组里运行，超时或结束时整组终止；用 `setsid`、`timeout` 等另开进程组或会话的子进程不在清理范围内，超时后可能继续运行。命令应为快速只读检查，不要在其中启动后台或脱离进程组的进程。输出（stdout 与 stderr 合并）按服务进程环境里的密钥值脱敏，保留前 4 KB；计划卡片显示命令、最近一次结果、输出和自上次通过以来连续跳过的次数，运行记录里只留一句摘要（退出码和输出末尾）。
- 只能在 Web 计划面板或本机 `dutydeck schedule --condition-command` 设置、修改或清除（要求安装管理员身份）。`dutydeck agent schedule create/update`、飞书 `/schedule` 与确认卡都不接受这个字段，请求里带了就返回 400。不能和「CI 出现新的失败构建」条件同时设置；模板计划可以用。目前只在 Linux 上可用。
- 命令命中默认高危规则（如 `rm`、`sudo`、`git push/reset`、`curl -X POST`）时拒绝保存。这只防手误，不是安全边界：能改计划的人本来就能在这台机器上执行命令，请只写只读检查。
- 命令单独保存，和计划修订号一次写入；计划本身的执行条件仍是「每次到期执行」。切回不认识前置命令的旧版本后，前置命令不再生效，计划每次到点都会唤醒 Agent，见[升级说明](upgrading.md)。

```bash
# 每 5 分钟看一次，工作区里有 ready.flag 才唤醒 Agent；超时 10 秒
dutydeck schedule create --session ses_xxx --name 等就绪 --prompt '处理新到的数据' --every 5 --condition-command 'test -f ready.flag' --condition-timeout 10
# 清除前置命令（也可 --input '{"precondition":null}'）
dutydeck schedule update schedule_xxx --session ses_xxx --condition-command ''
```

`--deadline` 接受带时区偏移的 ISO 时间，或按计划时区解释的 `YYYY-MM-DDTHH:mm`。API 的创建与更新字段同名（更新传 `null` 清除），`deadlineAt` 须带时区偏移；`GET /api/sessions/:sessionId/automation` 返回 `runStates` 和 `preconditions`（各计划的前置命令与最近一次结果），`GET /api/automation/schedules` 每项返回 `runState`。
