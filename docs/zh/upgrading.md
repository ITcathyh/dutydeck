# 升级说明

> [← 返回 README](../../README.md) · [全部文档](../../README.md#docs) · [English](../en/upgrading.md)

- **setup 终端预检不再迁移旧数据库**：检测终端 Agent 后，读取 `dutydeck.terminal_backend` 改为只读 SQLite 查询，不再打开仓储层。已有库不会因此跑 migration、写控制表或改变 schema 版本；后续 `--cwd` 校验失败或用户取消也保持原库不变。数据库、`configs` 表或设置键缺失时沿用 tmux 默认值，无效设置提示读取失败并跳过 tmux 预检。没有新增命令、设置或数据库迁移。
- **doctor 逐条隔离无效机器人配置**：`lark.exposure` 遇到单条无效配置时只跳过该条并报告数量，继续评估其余有效机器人；非回环无认证、完全信任、广范围高危和风控关闭等危险组合仍按原规则 fail/warn，不再被同数组里的坏条目整体降为 skip。整份配置不可解析时仍降级，修复指引继续由「飞书配置」检查给出。
- **doctor 核对停止 service 的 socket 实际状态**：daemon 记录中有 systemd unit 时，即使 service 当前未运行，也会通过 `TriggeredBy` 找到关联 `.socket`，再查询 `ActiveState` 与 `SubState`；只有 `active + listening` 才记为正在监听。查询失败、属性缺失或状态矛盾时返回 unknown，`lark.exposure` 降级为 skip，不再按 `.env` 的回环地址猜安全。socket 实际地址仍需用 `ListenStream=` 人工核对。

- **Claude 原生提问的选项说明（卡面变化）**：带 `description` 的 Claude 原生提问，卡片把说明从问题正文末尾移到对应选项下方显示，正文不再重复。说明是最长 1000 字符的可选纯文本，计入整卡长度预算，纯文本回退和全文附件里仍保留。没有说明的提问和旧记录布局不变，请求 ID、答案值和超时不变；旧程序会忽略该字段，继续显示 label/value。
- **飞书取消/中断结果卡可显示操作者**：账本记录了主动中断操作者时，结果卡会按 open_id 解析一次成员姓名，能解析时增加「由某用户取消」。查询失败、权限不足、机器人或系统身份无法解析时保持原有卡面文案，不阻塞终态投递；没有中断操作者证据的排队取消不会猜测发起人。名称和回退结论随卡片输入冻结，发送重试、重启补偿与旧卡重绘不重复查询；卡片回调与账本字段不变，无需新增设置。
- **Web 排队 / 立即中断的响应未知重试**：同一草稿的同一份完整提交在服务端已接受、浏览器却没收到响应时，手动重试会复用幂等键并取回原任务，不再重复执行；收到接受回执、编辑提交内容或选择「重新加入队尾」后，再次发送使用新键。`steer` 不自动重试，响应未知时先核对现有任务。旧客户端不传 `idempotencyKey` 的行为不变；给 `steer` 显式传该字段会在执行前返回 400。
- **同机不同端口的 Web 登录 Cookie**：Host 带合法显式端口时，登录 Cookie 改用 `dutydeck_access_<port>`，不再互相覆盖；无显式端口仍用 `dutydeck_access`。旧 Cookie 仍按本实例验证接受；显式端口下，共享 legacy 只有验证通过才额外清除，无端口同名 Cookie 保留旧登出语义。只持有新端口 Cookie 的浏览器回滚旧程序后需要重新登录。
- **用户气泡长文本折行**：长 URL 和连续字符在用户气泡及其 Markdown 子树内折行，窄屏不再被撑出页面级横向滚动；Agent 输出、代码块横向滚动和复制文本不变。

- **最终正文后的同工具重复进度（IN6-01）**：少数原来失败的轮次现在会保留工具开始后的最终正文，但只有正文后同一非空 id 的重复非终态 `tool_call` 才被忽略。工具前开场白、`tool_result`、`thinking`、无 id / 不同 id 和终态调用仍按原规则判失败；原始事件和输出 digest 不变，不需要设置或数据库迁移。

- **验证命令和计划前置命令按主进程退出结算（BM6-01，行为变化）**：主 Shell 已成功、后台后代仍持有 stdout/stderr 时，验证和计划前置命令不再把主进程误报为超时。以前因此被阻断的前置命令现在可能通过并触发一次计划；同一次 occurrence 只推进一次，通过后的崩溃恢复沿用原幂等键继续，不重跑该次已通过的前置命令。主进程真实超时、非零退出、结果结构和退出码含义不变。主进程退出后仍 SIGKILL 同组资源，并有界等待组退出和管道排空；同组资源未退出或可观察管道未排空仍写清理错误并阻断。完全脱离进程组且重定向管道的后代不承诺已被清理。

- **Claude 后台 Agent 续派分代（BM6-06）**：支持 `resumedAgentId` / `revivedAgentId` 的 Claude 会话在续派后按通知自身时间和转写位置建立新运行代次，后台计数和完成通知可能与旧版本不同。旧代迟到完成不会清新代，同时间戳或缺时间不会猜测复活；重放幂等，不自动重发续派指令，普通 Bash / Monitor 不变。

- **Agent 环境暂不可用的计划（EV6-01）**：`AGENT_UNAVAILABLE` 不再触发 fresh-session 补跑，也不按连续失败计数自动停用计划；本次 occurrence 和同因提示仍会记录，下一正常日程可以再推进，恢复后清零。已接受或结果未知的执行先对账；模型内容失败、权限拒绝、用户停止和其他错误策略不变。

- **慢工作项调度日志（EV6-02）**：上一轮 tick 未完成时，每秒回调直接跳过，不再叠加 wrapper；日志次数和 duration 只反映真实推进，可能比以前更少，不表示吞吐提升。直接调用 tick 仍共享 Promise，工作项时序、持久状态和恢复语义不变。

- **异常退出历史与回滚**：`last-abnormal-exit.json` 新增最近 10 条 `history`（按 runId+database 去重），以及同样按 runId+database 去重、各保留最近 10 代的 `lifecycleRuns`/`cleanExits`；单数 `lifecycle`/`clean-exit` 保留当前代兼容展示，顶层仍是最近一条旧枚举 `fatal|startup`，旧程序仍能读取顶层异常；但旧程序再次写异常文件会丢掉新增 history 和生命周期/干净退出元数据，不能据此恢复历史。Linux/systemd 可在精确匹配退出记录后补充 SIGKILL；launchd 富集尚未验证，不声明支持。
- **schema 过新错误更可行动**：`DATABASE_SCHEMA_TOO_NEW` 和备份版本不匹配错误会列出数据库版本、程序支持版本及带实际路径的只读 `dutydeck database execution-status --database <数据库路径>`。打开仍会被拒绝，不自动迁移或降级；切回旧代码不是数据库回滚，使用备份恢复会丢备份后的写入。
- **doctor 暴露组合检查（CT6-10）**：新增 `lark.exposure`，把监听地址、显式 local-only、local/token/open 认证、socket 激活、完全信任、高危用户范围与风控模式放在同一项判断。只有非回环无认证叠加可运行完全信任、广范围高危用户和弱风控时才新增 warn/fail；正常配置不新增失败。报告只含非机密的范围与数量，不自动修改 `.env`、unit 或机器人配置。socket 实际地址不可知或机器人配置不可读时降级为 skip，不猜测；既有 `access.posture` 等检查及回滚行为不变。

- **Claude 守卫按真实启动记录判定，缺策略时不再启动 Node**：每次真正拉起或重拉 Claude（包括恢复会话）时，记录本次实际设置里的守卫接线和当次能力探测结果；后续受保护轮次及服务重启后的终端接管只使用这份记录，不再逐轮探测磁盘 CLI，也不扫描未加载的历史设置。磁盘 CLI 后续升级不会误拒旧进程，降级也不会让启动时缺少 `onFailure: "block"` 的进程获得错误信任；启动探测失败按该次启动记录，不在每轮重试。从旧版升级后，仍在运行但没有启动记录的旧终端无法证明实际配置，受保护发送会保持拒绝，请重开会话（飞书发 `/new`）。另外，凭据守卫在会话 ID 为空或本轮策略文件不存在时由 shell 直接放行，不启动 Node；文件存在才读取，读取错误、损坏 JSON 和脚本失败仍阻断。没有新增设置、命令或数据库迁移。

- **Claude 守卫失败阻断需要官方 Claude Code 2.1.295+**：Dutydeck 自己的凭据与计划守卫在官方 Claude Code 2.1.295+ 上新增 `onFailure: "block"`，超时及未被现有 `|| exit 2` 覆盖的失败不再退回普通权限流程；策略读取/JSON 解析错误和 active 计划脚本缺失也会拒绝。旧版、探测失败和未验证分支不写这个字段，受保护轮次照常提交，守卫超时维持原行为，显式拒绝和脚本崩溃仍由 `|| exit 2` 拦截。恢复或接管的新版终端核对 marker、精确 matcher、command type 和实际 `onFailure` 形状；旧版不因缺少该字段被判为未接线。Ask relay、PermissionRequest 和用户 hooks 不变；没有新增设置、命令或数据库迁移。

- **新增只读日志命令**：`dutydeck logs [-n N] [--unit <unit>]` 默认查看最近 50 行，行数可设为 1–10000。不带 `--unit` 时读取当前 daemon 日志文件的末尾，带 `--unit` 时通过无 shell 的流式 `journalctl --user` 子进程读取对应 systemd 用户实例，两种来源最多保留末尾 256KiB；首版不 follow。带 `--unit` 时先取原始最近 N 行，再过滤疑似秘密，所以可能少于 N 行。普通行、错误行和多行堆栈按原顺序输出，疑似含秘密的整行过滤，unit 不存在或尚无日志会明确报错。它不写配置、不改原始日志或数据库；回滚到旧版本只是没有该命令，已有日志不受影响。
- **插件升级会显示执行命令变化**：`plugin update` 现在列出斜杠命令、Agent 启动配置和 hook 执行规格的标识与前后 SHA-256 摘要，JSON 结果增加 `changes`。交互终端会要求重新信任这些变化，拒绝时不写候选；非交互且未带 `--yes` 只打印变化，不新增失败，`--yes` 行为不变。仅描述变化不产生摘要，候选没有新的执行内容变化时不重复提问。活动版本仍需按原流程执行 `plugin activate`，不会在 update 中执行候选命令。
- **`dutydeck update` 支持精确版本**：可运行 `dutydeck update 1.2.3`，版本参数与 `--dist-tag` 互斥；无参数时仍使用 `latest`。安装、版本核对或重启失败会附 `npm install --global @byted/dutydeck@<实际旧版本> && dutydeck restart` 的手工回退步骤，直接重装旧包，不依赖旧版 CLI 是否认识 `update [version]`；旧版本不能安全放入命令时则明确说明，不自动回滚。
- **tmux 预检**：`doctor` 新增 `terminal.backend`，在独立临时 socket 上检查 tmux 命令、版本和会话建退，不碰默认 server；所有调用使用 `-f /dev/null` 和私有 `XDG_CONFIG_HOME`，测试会话只运行受控命令，不加载系统或用户配置。setup 对需要 tmux 的终端 Agent 增加一行同类警告，缺失或失败不阻止写配置。纯 ACP 与 Herdr 配置不因缺 tmux 报致命错误。
- **无机器人时的首启提示**：前台交互启动且读不到机器人配置时，监听地址下每次都会显示 setup、doctor 和实际 Web 地址，不新增展示状态配置；`--json`、非 TTY 和 daemon 子进程不显示。CLI 不在 `PATH` 时增加通用修复提示。
- **setup 飞书收发验证改为用户先发起**：专用确认默认 No；同意并启动临时监听后，终端显示一次性 UUID，由用户在飞书里私聊机器人发送这段验证码。只有在有界时间内收到包含本次 UUID 的用户私聊，机器人才回复该消息并携带同一 UUID。飞书接受回复表示入站通过、出站已发送，用户仍需在飞书确认收到；超时则入站未验证，且不发送任何消息。`--yes`、非交互和 `--json` 不进入该验证。此流程不改变机器人权限，也不持久化用户 open_id。

- **Claude 家族终端的空闲压缩改为原生维护输入**：沿用现有 `idleCompactEnabled` / `idleCompactHours`，没有新增设置或数据库迁移。达到阈值后的下一条消息先执行 `/compact`，只有本次输入回执、同会话手动边界和同代摘要共同证明成功才继续；维护本身不生成业务轮次。明确失败和未支持 CLI 继续原消息，取消不写原消息；无法证明终端恢复时，原消息按“未提交”失败，不按“结果未知”自动重发。后续每次输入会重新确认终端，恢复后正常继续；持续无法确认时本次仍不写入，可稍后重发或发 `/new` 开新会话。已验证 Claude Code 2.1.220；回滚旧程序不会撤销已经完成的原生压缩，旧程序会把这条终端维护能力视为不支持并继续后续业务。

- **tmux 会话生命周期**：Linux 上 tmux socket 文件被清理但旧 server 仍在时，启动会拒绝另建同名 server，并提示用 `SIGUSR1` 重建 socket 或结束旧 server；不会再让两个 CLI 接管同一会话。启用 `remain-on-exit` 时，下次启动会回收 Dutydeck 自有且全部 pane 已退出的死会话，仍有 pane 运行的会话保留。非 Linux 行为不变。

- **飞书会话提醒在原消息撤回后改为新发**：排队受阻、排队超时取消、结果未知这类会话提醒要回复的原消息已被撤回时，从丢失改为在原会话（群或私聊）里新发一条，服务日志记一条「回复会话提醒失败，回退为会话内发送」告警。定时任务的提醒与同一计划的其他投递一致，仍不改发；超时这类结果未知的失败也不改发。不需要配置。
- **长路径工作目录的 Claude 会话**：工作目录路径编码后超过 200 个字符时，Claude Code（2.1.224 起）把转写写进截断加哈希的项目目录，以前 Dutydeck 找不到这份转写。现在新旧两种目录都会读，按具体会话文件和内容核验选择：服务重启后照常续接，结果和用量按转写读取。这类会话的用量从此开始计入，可能触发月度上限；完成判定从看屏幕改为看转写；找到了会话文件却读不出 Dutydeck 标记，或新旧目录里各有一份同一会话且无法核对时，从悄悄新开改为明确拒绝续接。200 个字符以内的路径行为不变；回滚到旧程序后只认不截断的旧目录，没有数据残留。
- **Claude 会话内定时任务触发的那一轮**：Claude 终端会话里用 `CronCreate` 建的定时任务到点后，Claude 会自己起一轮。以前这一轮的回答会被当成上一条或正在等待的那条消息的输出；现在它作为后台结果单独显示在会话里，不计入任何一条消息的结果，也不会让正在进行的那一轮提前结束。只识别 Claude Code 2.1.318 写下的定时触发记录；其他自动唤醒方式保持原样。
- **新增机器人设置 `claudeAutoMemory`**：默认 `inherit`，行为不变。设为 `off` 后，开着会话记忆的机器人在群聊里新拉起的 Claude 进程关闭 Claude 自带的 auto memory，已有会话在下次拉起时生效并续接原会话（见[跨会话长期记忆](features.md)）。`features.md` 里「各群记忆互不可见」改为只指 Dutydeck 群记忆。回滚到旧程序后设置失效；旧程序保存该机器人的配置时会丢掉这个键，再升级回来是 `inherit`。
- **工作区写法不同也能续接飞书会话**：机器人配置的工作区和会话记下的工作区写法不同（符号链接、末尾带 `/`、含 `..`），但指向同一个目录时，重启后改为续接原会话，不再另开新会话；写法相同时行为不变。升级后首次重启，以前因为写法不同而没被选中、仍在活动的会话可能被重新选中（同一作用域取最近创建的一条），续接上放了好几天的上下文；不想续接就在飞书发 `/new`。更早被这样换掉的旧会话从没停止过，也不会自动清理，请到 Web 上归档（归档会停止仍在运行的会话）。独立 worktree 会话的 `/status` 不再显示「配置的工作区」，改为写明它基于哪个工作区。
- **迁移记录核对迁移名**：数据库的迁移记录新增迁移名。升级后首次启动时给已有记录补上迁移名，并补建 v47–v49 中缺失的索引。之后若同一版本号记录的迁移名与程序不一致（数据库被其他分支的程序升级过），启动直接报 `DATABASE_SCHEMA_LINEAGE_MISMATCH` 并停止，不再跳过该迁移或在升级中途失败；这时恢复用那个程序之前的数据库快照，或继续用写入它的程序。较旧的程序仍能打开带迁移名的数据库。
- **历史摘要索引（v47）**：升级时为事件表建立一条读取索引，会话历史摘要读取更快，历史数据不变。首次启动时建索引的耗时随事件数增长，约 24 万条事件的库在冷缓存下多花约 3.5 秒，之后启动不受影响；索引每万条事件约占 1 MB 磁盘。迁移后，较旧的程序会因数据库版本较新而拒绝启动。
- **定时计划前置命令（升级与回滚）**：新增的前置命令单独存一条记录，计划本身不加字段、执行条件仍写「每次到期执行」，不需要数据库迁移，没设前置命令的计划行为不变。切回旧版本时，旧程序照常读计划，但不认识前置命令：命令不再执行，计划每次到点都会唤醒 Agent；再升级回来后，原来保存的命令重新生效。如果把条件直接写成计划的新条件类型，旧程序的严格解析会把整条计划判为无效记录（不再列出、按编号读取报错、不再触发），所以没有这样做。用法见[通用定时任务](web-console.md)。
- **稳定性**：终端和实时流建连失败或握手超时后会按原规则重连，实例代理配置只接受 `http:` 地址。定时委托、记忆、插件和历史读取会使用已核验的自动容量重试结果，人工重试仍单独处理；PR 后台跟进失败会记录日志，后续轮询仍可恢复，无需新增设置。租约交接后，当前执行者可继续准备尚未开始执行的定时委托任务，并投递明确尚未发送的结果；旧版因已验证的自动容量重试而阻塞的定时任务和 CI 续作可恢复一次交付，其他未知状态不自动解除。
- **长会话与实时更新**：连接状态与记录追平状态分开；已结束轮次先读摘要，展开后读完整记录。原始日志可显式完整查看、复制和导出，无需新增设置。
- **飞书消息处理**：收到消息后及时发起确认表情，同时继续准备任务；任务结束后清理晚到的确认。上下文读取超时会停止本轮后续读取，失败提示和重试时可读取的材料保持不变。同一机器人的并发认证请求合并，各请求仍遵守自己的等待与重试预算。已关闭的历史交互卡与结果验收反馈减少重复读取，历史查看、失败重试和到期提醒继续可用。
- **原生日志读取**：Codex 同一原生会话切换日志后，用量读取会定期重新定位当前日志。Codex / TraeX 的会话来源核验改为分段执行，保留原有完整日志扫描和归属检查，扫描期间让其他请求继续处理。
- **密钥存储锁**：修改密钥的锁在连接关闭或进程崩溃退出后由系统释放。升级时需同步更新所有密钥写入端，新旧版本混用不保证互斥；旧 `.lock` 文件不再阻塞新版操作，新的 `.lock.sqlite` 文件须保留。密钥存储包新增对项目现有 `better-sqlite3` 的依赖，安装时需要其原生模块可用。
- **长会话历史索引（v49）**：在 v47 历史摘要索引之外，升级时再为用户消息建立读取索引，切分轮次和生成跳转标签时不再逐条解析事件；建索引要读一遍已有事件，事件很多的库升级会多花一些时间，历史数据不改写。会话历史接口新增 `GET /api/sessions/:id/history?tail=<1–1000>`（只摘要最近若干轮，另附每一轮的位置）和 `GET /api/sessions/:id/history/turns?from=&through=`（按事件序号范围读已结束轮次的摘要），不带参数的 `/history` 返回内容不变。迁移后，较旧的程序会因数据库版本较新而拒绝启动。
- **飞书入站记录索引（v48）**：升级时为飞书入站记录建立读取和保留期清理用的索引，已有记录不改写。迁移后，较旧的程序会因数据库版本较新而拒绝启动。
- **查询索引（v42）**：升级时为会话、用量事件、自动化和提问状态建立读取索引，历史数据保留；持久化提问按编号读取，正在等待回答的提问仍即时可用。迁移后，较旧的程序会因数据库版本较新而拒绝启动。
- **终端尺寸**：调整终端大小只接受正整数行列；无效请求返回错误后，连接仍可继续使用。
- **工作项并发**：工作项子步骤实际执行最多全局 6 个、每个工作项 3 个；其准备和已接受队列全局最多 12 个、每工作项最多 3 个。纯排队不占执行名额，也不消耗一小时执行期限；工作区互斥和未知执行的保守占用继续生效。
- **工作项恢复**：因执行结果未知而暂停的步骤，通过正式恢复接口核对原执行并确认成功后，会在下次调度继续剩余步骤；确认失败后可重试该步骤。恢复前重新核对权限和配置，已完成步骤不会重跑。结果仍不确定、工作已取消或审查要求停止时保持暂停。
- **工作项计划修订**：升级时更新工作项索引，使修订删除的步骤仍保留子会话归属，已有记录不改写；迁移后较旧的程序会因数据库版本较新而拒绝启动。用法见[目标计划修订](web-console.md#work-plan-revision)。
- **工作项历史**：升级时自动建立调度索引，已完成且交付结束的记录不再进入每秒扫描；历史仍可查看，未交付结果继续重试。发送失败按 1、2 分钟退避重发（服务重启后不等退避，立刻补发），最多 3 次，之后停在“送达失败”并在工作项上显示原因，不再自动重发。
- **空闲开销**：飞书过程卡有新事件时照常刷新；没有新事件时每 10 秒刷新一次用时（原来每秒一次）。每小时的群同步在群名不变时不再写版本记录，退群检测覆盖全部群（原来只看前 500 个）。飞书入站消息日志带事件类型和事件 ID；有人入群的事件不再触发 SDK 的未处理告警。
- **断线与停止恢复**：跨实例实时流断开后可重新连接；服务关闭会回收代理连接和建连中的飞书监听。终端首次停止失败后可再次尝试回收进程。
- **后台任务**：空白回答不再阻塞后续记忆提取；群通知按完整一小时窗口计算额度；cron 修复跨年闰日和夏令时重复时段。已启用的周期计划缺失下次执行时间时自动补算，已结束的单次计划不会重新执行。
- **Web 任务状态**：连续出现的实时事件缺口会继续补齐，并刷新任务状态；迟到的任务列表响应不会覆盖同一轮已收到的新状态。
- **GitHub 读取边界**：PR 普通评论和行内评论支持分页，两类合计最多 100 页、8 MiB；超出时整次读取报错，不返回部分评论。单个 JSON 响应最多 2 MiB，单个日志实际下载最多 8 MiB，超限会取消读取；日志超限时仍返回失败任务和步骤摘要，但不附日志。最多并发读取 10 个失败 job 的日志，结果保持 job 顺序，单条日志失败不影响其他日志。
- **CLI 启动**：减少 `secret` 等本地管理命令的启动开销。
- **CI 环境变量迁移到插件**：见[插件 → 升级说明](plugins.md)。`DUTYDECK_GITHUB_TOKEN`、`GH_TOKEN`、`GITHUB_TOKEN`、`DUTYDECK_CODEBASE_WEBHOOK_SECRET` 不再生效，要装插件、用 `dutydeck plugin config … --value-fd 0` 填值并重启。
- **告警初筛改为内置场景包 `alarm`**：群里的说法、确认卡、来源、级别、去重和每小时上限不变；已有订阅在升级时自动转成 `alarm` 包的绑定，升级前发出的确认卡照常能点。变化有三处：初筛任务的 prompt 里告警原文改为不可信材料放在指令后面；关联带给 Agent 的上一轮结论也改为不可信材料；判断是否重复只查本包的初筛记录，群里其他判定记录再多也不会让同一条告警重复初筛。命令行改用 `scenarios=`，`alarm=` 保留一个版本。
- **告警初筛包升到 1.1.0，告警下的话题改为可以接追问**：多机器人群里，以前来源机器人发的告警开出的话题算别的机器人的话题，没 @ 的追问一律不接；现在这类话题不算别人的，只有别的机器人已在里面发过言、话题超过 4 页读不完或读取失败时才让路。两个机器人同时判定时可能都接。已有绑定按新版本生效，不用重新确认。
- **`model` 模式场景包可以用了**：以前加载时会拒绝，现在照常加载，例子见 `plugins/team-faq`。
- **数据库升到 v38 后旧版本打不开**：v38 把群分工改成按场景包存绑定。升级后再换回旧版本会因为数据库版本比程序新而拒绝启动（`DATABASE_SCHEMA_TOO_NEW`）。出了问题只能向前修复，或者恢复部署前的数据库快照，快照之后的全部写入都会丢。
- **强制拦截的工作区 Hook 加入凭据检查（v3）**：已经开了强制拦截的机器人，要在 Web 设置里重新点「配置拦截 Hook」或运行 `dutydeck settings bot install-hook <app-id>`，Codex ACP 的凭据检查才生效；重装前保存这个机器人的设置会提示 Hook 未就绪。默认 Agent 是 Claude Code 终端（含 ccflash 这类自定义 Agent）或经 Dutydeck 启动的 ACP Claude 的机器人不受影响，现在可以直接开强制拦截。
- **Agent 的命令统一到 `dutydeck agent`**：提示词缩成一段，不再带轮次凭证；Agent 代你查看状态、任务、排队等时不再在群里发结果卡，改为在答复里说明。旧命令保留，升级前已经在跑的会话照常可用。见[给 Agent 用的命令行](cli.md)。
- **每轮改动漏记已修复**：以前，一次索引写入后同一秒内又改了某个文件、且文件大小没变时，“每轮改动”会漏记这个文件（影响「查看改动」和 `/pr` 的文件清单）。现在已修复。
