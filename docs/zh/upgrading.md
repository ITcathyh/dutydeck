# 升级说明

> [← 返回 README](../../README.md) · [全部文档](../../README.md#docs) · [English](../en/upgrading.md)

- **稳定性**：终端和实时流建连失败或握手超时后会按原规则重连，实例代理配置只接受 `http:` 地址。定时委托、记忆、插件和历史读取会使用已核验的自动容量重试结果，人工重试仍单独处理；PR 后台跟进失败会记录日志，后续轮询仍可恢复，无需新增设置。租约交接后，当前执行者可继续准备尚未开始执行的定时委托任务，并投递明确尚未发送的结果；旧版因已验证的自动容量重试而阻塞的定时任务和 CI 续作可恢复一次交付，其他未知状态不自动解除。
- **长会话与实时更新**：连接状态与记录追平状态分开；已结束轮次先读摘要，展开后读完整记录。原始日志可显式完整查看、复制和导出，无需新增设置。
- **飞书消息处理**：收到消息后及时发起确认表情，同时继续准备任务；任务结束后清理晚到的确认。上下文读取超时会停止本轮后续读取，失败提示和重试时可读取的材料保持不变。同一机器人的并发认证请求合并，各请求仍遵守自己的等待与重试预算。已关闭的历史交互卡与结果验收反馈减少重复读取，历史查看、失败重试和到期提醒继续可用。
- **原生日志读取**：Codex 同一原生会话切换日志后，用量读取会定期重新定位当前日志。Codex / TraeX 的会话来源核验改为分段执行，保留原有完整日志扫描和归属检查，扫描期间让其他请求继续处理。
- **密钥存储锁**：修改密钥的锁在连接关闭或进程崩溃退出后由系统释放。升级时需同步更新所有密钥写入端，新旧版本混用不保证互斥；旧 `.lock` 文件不再阻塞新版操作，新的 `.lock.sqlite` 文件须保留。密钥存储包新增对项目现有 `better-sqlite3` 的依赖，安装时需要其原生模块可用。
- **查询索引（v42）**：升级时为会话、用量事件、自动化和提问状态建立读取索引，历史数据保留；持久化提问按编号读取，正在等待回答的提问仍即时可用。迁移后，较旧的程序会因数据库版本较新而拒绝启动。
- **终端尺寸**：调整终端大小只接受正整数行列；无效请求返回错误后，连接仍可继续使用。
- **工作项并发**：工作项子步骤实际执行最多全局 6 个、每个工作项 3 个；其准备和已接受队列全局最多 12 个、每工作项最多 3 个。纯排队不占执行名额，也不消耗一小时执行期限；工作区互斥和未知执行的保守占用继续生效。
- **工作项恢复**：因执行结果未知而暂停的步骤，通过正式恢复接口核对原执行并确认成功后，会在下次调度继续剩余步骤；确认失败后可重试该步骤。恢复前重新核对权限和配置，已完成步骤不会重跑。结果仍不确定、工作已取消或审查要求停止时保持暂停。
- **工作项历史**：升级时自动建立调度索引，已完成且交付结束的记录不再进入每秒扫描；历史仍可查看，未交付结果继续重试。发送失败按 1、2 分钟退避重发，最多 3 次，之后停在“送达失败”并在工作项上显示原因，不再自动重发。
- **空闲开销**：飞书过程卡有新事件时照常刷新；没有新事件时每 10 秒刷新一次用时（原来每秒一次）。每小时的群同步在群名不变时不再写版本记录，退群检测覆盖全部群（原来只看前 500 个）。飞书入站消息日志带事件类型和事件 ID；有人入群的事件不再触发 SDK 的未处理告警。
- **断线与停止恢复**：跨实例实时流断开后可重新连接；服务关闭会回收代理连接和建连中的飞书监听。终端首次停止失败后可再次尝试回收进程。
- **后台任务**：空白回答不再阻塞后续记忆提取；群通知按完整一小时窗口计算额度；cron 修复跨年闰日和夏令时重复时段。已启用的周期计划缺失下次执行时间时自动补算，已结束的单次计划不会重新执行。
- **Web 任务状态**：连续出现的实时事件缺口会继续补齐，并刷新任务状态；迟到的任务列表响应不会覆盖同一轮已收到的新状态。
- **GitHub 读取边界**：PR 普通评论和行内评论支持分页，两类合计最多 100 页、8 MiB；超出时整次读取报错，不返回部分评论。单个 JSON 响应最多 2 MiB，单个日志实际下载最多 8 MiB，超限会取消读取；日志超限时仍返回失败任务和步骤摘要，但不附日志。最多并发读取 10 个失败 job 的日志，结果保持 job 顺序，单条日志失败不影响其他日志。
- **CLI 启动**：减少 `secret` 等本地管理命令的启动开销。
- **CI 环境变量迁移到插件**：见[插件 → 升级说明](plugins.md)。`DUTYDECK_GITHUB_TOKEN`、`GH_TOKEN`、`GITHUB_TOKEN`、`DUTYDECK_CODEBASE_WEBHOOK_SECRET` 不再生效，要装插件、用 `dutydeck plugin config … --value-fd 0` 填值并重启。
- **告警初筛改为内置场景包 `alarm`**：群里的说法、确认卡、来源、级别、去重和每小时上限不变；已有订阅在升级时自动转成 `alarm` 包的绑定，升级前发出的确认卡照常能点。变化有三处：初筛任务的 prompt 里告警原文改为不可信材料放在指令后面；关联带给 Agent 的上一轮结论也改为不可信材料；判断是否重复只查本包的初筛记录，群里其他判定记录再多也不会让同一条告警重复初筛。命令行改用 `scenarios=`，`alarm=` 保留一个版本。
- **告警初筛包升到 1.1.0，告警下的话题改为可以接追问**：多机器人群里，以前来源机器人发的告警开出的话题算别的机器人的话题，没 @ 的追问一律不接；现在这类话题不算别人的，只有别的机器人已在里面发过言、话题超过 4 页读不完或读取失败时才让路。两个机器人同时判定时可能都接。已有绑定按新版本生效，不用重新确认。
- **`model` 模式场景包可以用了**：以前加载时会拒绝，现在照常加载，例子见 `plugins/team-faq`。
- **数据库升到 v38 后旧版本打不开**：v38 把群分工改成按场景包存绑定。升级后再换回旧版本会因为数据库版本比程序新而拒绝启动（`DATABASE_SCHEMA_TOO_NEW`）。出了问题只能向前修复，或者恢复部署前的数据库快照，快照之后的全部写入都会丢。
- **强制拦截的工作区 Hook 加入凭据检查（v3）**：已经开了强制拦截的机器人，要在 Web 设置里重新点「配置拦截 Hook」或运行 `dutydeck settings bot install-hook <app-id>`，Codex ACP 的凭据检查才生效；重装前保存这个机器人的设置会提示 Hook 未就绪。默认 Agent 是 Claude Code 终端（含 ccflash 这类自定义 Agent）或经 Dutydeck 启动的 ACP Claude 的机器人不受影响，现在可以直接开强制拦截。
- **Agent 的命令统一到 `dutydeck agent`**：提示词缩成一段，不再带轮次凭证；Agent 代你查看状态、任务、排队等时不再在群里发结果卡，改为在答复里说明。旧命令保留，升级前已经在跑的会话照常可用。见[给 Agent 用的命令行](cli.md)。
- **每轮改动漏记已修复**：以前，一次索引写入后同一秒内又改了某个文件、且文件大小没变时，“每轮改动”会漏记这个文件（影响「查看改动」和 `/pr` 的文件清单）。现在已修复。
